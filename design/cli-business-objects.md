# 业务对象定义

状态：用于本轮场景和输出设计的业务模型基线，2026-11-08；不表示能力目录、新领域类或 text 已实现。现有公共 ID 不变，不要求为每个概念新建表或聚合根。

## 1. 识别与使用规则

产品场景 P01–P15 与六格说明用户要解决什么问题，支撑能力 C01–C31 说明怎样组合业务能力；本文件的 O01–O30 说明参与哪些对象及其不变量。B1–B7 的规则归属与当前代码边界见 [DDD 实现分析](ddd-implementation-boundaries.md)，不要求一格/一个对象对应一个模块、聚合或数据表。

| 项目 | 规则 |
|---|---|
| 识别来源 | 从业务价值、权威规则和 [领域边界](cli-business-capabilities.md) 识别，代码证明约束，不直接照抄 struct |
| 对象范围 | 实体、值对象、契约、业务过程和读模型均有明确业务含义；30 项是对象族，不是 30 个聚合根 |
| 权威 | 每项有主要责任边界，跨边界通过引用/本地模型消费事实，不制造第二份真相 |
| 状态 | 有独立生命周期才定义状态机；配置、签名和证据等值不强造 queued/running |
| 主动任务与内部组成 | 对象存在不意味着有独立 CLI 增删改查；现有任务见 [业务场景](cli-application-scenarios.md)，按目的、主交付物和验收命名动作＋对象，不机械计算对象×动作 |
| 默认展示 | 业务上需要身份不等于 text 必须输出全部 ID；保留可定位性和歧义边界 |

O01–O30 为文档引用编号，不是产品新增公开 ID；编号顺序不代表优先级或执行顺序。核心生成/查询按目标、交付物和手段区分。场景需要用户目的、输入及交付验收，不能由对象和操作标签机械相乘得到。

## 2. 核心：agent 交互契约（B1）

| 编号/对象 | 职责与形态 | 身份/取值 | 状态或变化 | 不变量与关系 |
|---|---|---|---|---|
| O01 能力契约 | 定义 agent 可发现和使用的一项业务能力；版本化契约 | 操作名、支持版本、参数/互斥规则、语言/上下文条件、输入输出类型、效果与限制 | 随产品能力/契约版本演进；不是本机 ready 状态机 | help 与请求校验是同一能力规则的呈现/执行；静态支持不保证当前就绪；引用 B2/B3 语义规则与 O17 条件，不能自己编造规则 |
| O02 业务请求 | 表达 agent 要调用什么、针对谁、受哪些条件约束；请求值 | 能力引用、规范化参数、项目/选择范围、策略；进入 daemon 时关联已有 RequestId | 构造、校验、受理或拒绝；执行生命周期属于 O18 | 请求不是任务；同请求 ID 的不同规范化内容必须冲突，同内容重试读取原任务；查询规格由 O12 定义，其他操作使用各自规格 |
| O03 结果交付 | 将业务结果及必要边界交给 agent；交付读模型/分页会话 | 业务答案或操作结果引用、所选格式、完整记录范围、实际 cursor；任务输出另有事件序列 | 已交付、仍有页/片段、输出受限、中断、过期等按可观察事实表达；不是统一的新数据库枚举 | 不改变 O13 的事实与 O22 的发布结论；交付未完不等于计算未完；完整写出不证明 agent 已读，断流未确认不能编造成功；text/JSON 分别计费；必要 header 跨页可恢复；保存/续页依赖 B6 的冻结与保护机制 |

help 是 O01 的核心业务视图，不是把任意字符串当作独立实体。版本号、参数约束、错误语义和输出解释属于契约；clap、stdout、protobuf、JSON 编码是实现方式。O01 当前规则分散在 CLI、preflight、LanguagePolicy、握手等处，尚无统一契约对象实现。

## 3. 核心：索引生成与更新（B2）

| 编号/对象 | 职责与形态 | 身份/取值 | 状态或变化 | 不变量与关系 |
|---|---|---|---|---|
| O04 分析项目 | 确定被理解的项目及隔离范围；实体/归属范围 | 现有 ProjectId；CheckoutId 区分工作副本，IndexTarget 区分索引目标 | 项目源码随时间改变，各次知识输入另行冻结 | project/checkout/target 不混用；路径不是唯一业务身份；模块/包组织及选择条件在项目范围内解释 |
| O05 分析上下文 | 确定相同源码在什么语言、模块、scope、依赖和配置下解释；语义上下文值 | 显式 world 及语言、module、scope、语义输入/配置身份；消费既有公共编码 | 对一次捕获/分析固定；语义条件变化形成不同上下文 | 同路径不等于同上下文；外部依赖可影响绑定；不是 dispatch 的 workspace-open/closed 假设，后者属于 O12/O10 |
| O06 源码单元 | 提供被分析的原文与可验证定位；捕获单元及位置值 | 上下文归属、项目相对路径、内容 hash；片段附 UTF-8 字节区间/UTF-16 行列 | 捕获后内容固定；活动读取可能发现 hash 不匹配 | 原文、空行、缩进和字符边界保真；同一物理文件可有多个分析实例；连续区间可合并，非连续不得拼接；资源/XML/控制输入按实际用途区分，不伪装语义源码 |
| O07 程序实体 | 表达 agent 能定位/理解的程序对象；实体族 | 已有公开 FactId、所属 O05、声明种类/签名、所属者及位置 | 在固定知识版本中不变；新版本可新增、删除或改变 | 子类包括类型/方法/函数/字段等声明、外部符号、公开框架配置节点；外部符号不保证源码可读；辅助 raw syntax/type/binding facet 不自动成为公开实体 |
| O08 源码注释 | 表达独立可搜索的注释正文与原文映射；注释实体 | 现有 CommentId、O06 来源/范围、kind、body、语言规则版本 | 随捕获源码及上下文固定；版本变化可形成新身份 | 可以无关联声明；documents/enclosing_callable 是实际语言关联，不能猜测语句归属；正文与原文命中通过映射校验；注释覆盖独立于绑定覆盖 |
| O09 语义关联 | 表达程序对象的结构/行为关联；关系与出现位置子型 | 直接事实使用已有公开 ID/owner；关系含端点/种类，occurrence 另含现场/来源/位置；派生关系按明确业务键识别 | 固定版本中保持实际多重性；增量按 owner 替换含删除/零输出 | 子型含包含/继承/override/配置/依赖关系，以及调用、引用、注解 occurrence 和注释链接；关系去重不等于 occurrence 去重；方向、环、不同元注解路径不能丢失 |
| O10 绑定结论 | 表达某实体/现场能确认或推导哪些目标及依据；证据化结论值 | 现场/实体引用、目标、producer 状态、来源；推导时另带算法/假设/证明 | 可为确认、可能、歧义、未解析或未知，保持 producer 已定义语义 | 已发布绑定的权威属于 B2；B3 可形成保留原绑定的派发候选视图，不把候选升级成确认；开放世界不证明穷尽实际运行目标 |
| O11 分析证据与覆盖 | 界定知识事实的可靠范围、来源和缺口；证据/覆盖值 | 被证明的实体/关联/文件/上下文、能力标签、来源、原因与完整性取值 | 随固定输入产生，修复输入后新版本可改善；不能追改历史缺口 | 缺诊断不等于完整；局部绑定和全局覆盖分别表达；B3 消费并形成答案证据，不靠报告/格式/下游 source 成功洗掉上游缺口 |

O09 必须按子型判定身份：两个调用现场可产生同一 from/to 关系，但仍是两次出现；同一直接注解经两条 meta 路径到达同名注解，也不是一条可任意去重的结果。

模块、包、源码根是 O04/O05 的组织与选择值；源码位置、参数、类型、修饰符是 O06/O07 的值；框架配置的 bean/XML/MVC 等公开节点是 O07 子类，不另造“其他知识”。

### 3.1 索引生成的业务规格、过程与成果

| 编号/对象 | 职责与形态 | 身份/取值 | 状态或变化 | 不变量与关系 |
|---|---|---|---|---|
| O27 索引生成规格与方案 | 定义目标、输入/基线、模式与政策；规格/方案值 | O04/O05、O15/O16/O17、目标、期望基线、模式意图、实际 full/delta/reuse 策略与参与单元 | 请求固定后形成可信方案；不兼容时调整实际策略并说明原因 | 意图不等于实际模式；无可信基线不能冒充增量；变化/删除/零输出都处理；IndexCommand/IndexPlan 是部分实现而非全部含义 |
| O28 语义索引 | 承载可支持代码问题的知识内容；核心内容集合模型 | 项目/目标/上下文、输入/语义身份、实体/注释/关联/绑定/覆盖及能力；引用 O21 现有版本身份 | 私有候选、验证后内容、发布后可查询；FILES 不冒充完整语义索引 | 内容/关系/多重性/覆盖/能力一致；与 O21 是同一物理内容的领域/历史模型，不复制事实；普通语义查询只读已发布内容 |
| O29 索引构建 | 从规格/输入生成候选索引及构建结果；核心业务过程 | O27、冻结输入、O18/目标/基线；产生 O28、实际模式/范围和质量，不新造 run ID | 规划→分析/增量/复用→校验→形成候选或失败；发布可用性由 O22 确认 | 不用通用任务状态代替构建语义；复用仍验证候选；质量/门禁/提交分开；不越过 O22 改 head |

O28 负责索引内容含义；O21/O22 负责版本承载和真实提交。发布事务是支撑能力，不意味着“生成可查询索引”整体属于支撑。

## 6. 支撑：任务执行（B5）

| 编号/对象 | 职责与形态 | 身份/取值 | 状态或变化 | 不变量与关系 |
|---|---|---|---|---|
| O18 执行任务 | 跟踪一次已受理业务请求的执行和控制；任务实体 | 现有 TaskId、RequestId/规范化请求摘要、项目/目标、事件序列、结果 | 当前 TaskPhase 为 queued/running/terminal/expired；终态含执行结果、质量、门禁、发布和报告事实 | 取消请求不是已取消终态；受理不是完成；重试不重放写操作；断流不是回滚；本地 prepare/export 不伪装成已经登记的 daemon task |
| O19 执行预算与用量 | 约束并核实执行消耗；预算、grant 与用量账本值 | 根任务/语言/实例 grant、额度、累计已核实水位、截止时间、完整/未知标记 | reserved/running/complete/failed/unknown 按真实回执；无最终回执可仅有最后核实水位 | 重试不重置额度或延长截止时间；未知不写成 0；共享账本不重复相加；查询与分析预算按各自规则处理 |
| O20 运行服务与执行资源 | 表达可观察/控制的用户级服务及其归属资源；服务实体和内部资源子型 | endpoint/generation/进程启动身份、任务/worker 所有权；不把 PID 当稳定业务身份 | 服务观察/排空/失联等以真实状态为准；worker 内部生命周期按后端契约 | status 不证明语义分析可用；stop 请求取消任务不等于已观察进程退出；restart 是组合操作；不能回收无归属证明的进程；hello 仅为连通性观察 |

任务执行结果的 completed/failed/cancelled、质量 complete/partial/unknown、gate、publication、report 是 O18 结果中的独立值，不再把每个布尔/枚举都包装为新业务实体。

## 7. 支撑：发布与历史（B6）

| 编号/对象 | 职责与形态 | 身份/取值 | 状态或变化 | 不变量与关系 |
|---|---|---|---|---|
| O21 知识版本 | 固定一组已发布事实与捕获来源，供一致读取；版本实体 | 现有 RevisionId、IndexTarget、manifest、profile、producer 和创建信息 | 从私有候选经验证发布；提交后不可原地变更；旧版本可受保护或被回收 | head 只是当前指向，不等于版本本身；旧格式需重建，不静默原地迁移；业务上需要版本身份不等于普通 text 必须打印 revision |
| O22 发布裁决与提交记录 | 决定本次发布是否允许、是否真实发生；发布流程结果/提交证据 | 关联 O18、目标、期望基线、O21、质量/策略和持久提交事实；复用现有 task/commit 标识 | 准备/取消或超时裁决→进入提交→以实际事务结果确认；终态可已发布或保留旧版，错误另有明确原因 | gate 通过不等于已提交；strict 不改善质量；取消不得撤销已准入提交的真实结果；报告/ack/交付失败不推翻提交；PublicationFence 是机制，不是发布业务对象的全部含义 |
| O23 历史快照 | 给 agent 可命名/读取的冻结项目状态；快照实体 | 项目内快照 ID、files/analysis、WORKTREE/Git 来源、manifest、可选 O21 引用、时间 | 创建/保存、同名更新、删除引用；引用内容由实际保存记录确定 | 当前存储允许同名替换，不能承诺名称永远绑定首次内容；analysis 必须关联已发布知识，files 不证明语义分析；删除引用不等于立即删图 |
| O24 资产维护计划与结果 | 评估/落实回收和残留清理；计划/效果值 | 范围、保留策略、受保护引用、候选资产/pending/orphan、preview/execute、实际效果 | 预览、执行时重新评估、成功/部分效果或失败按事实表达 | 预览不锁定未来效果；GC 不删仍受保护资产；recover 当前清理存储残留并检查活动任务数，不冒充通用进程恢复 |

O03 的冻结页也是有保护与过期规则的派生结果资产，由 B6 提供保存/保护机制，但它的业务单位是“本次答案的交付”，不是新的知识版本或用户历史快照。

## 8. 支撑：报告与诊断（B7）

| 编号/对象 | 职责与形态 | 身份/取值 | 状态或变化 | 不变量与关系 |
|---|---|---|---|---|
| O25 诊断发现 | 记录某阶段发现的问题、来源、影响和必要原始信息；诊断/分组记录 | 来源边界/任务/上下文、code/severity/phase、位置或无位置范围、消息、次数、影响依据 | 随对应事实/执行产生；可采样/归组但需明示省略；B7 消费各边界的原始结论 | 不无证据归因网络或某文件；backend/auxiliary 不冒充源文件；无诊断不等于语义完整；样例数不等于总发生次数；B7 不重写 B2/B4/B5 的事实权威 |
| O26 分析报告 | 保存并解释一次执行的实际结果，并支持可比指标对照；报告实体与比较读模型 | 现有报告 ID、创建信息、实际任务/版本/上下文、执行结果、诊断/度量、配置政策 | 报告引用有 off/pending/saved 状态；保存的报告可被读取、比较、回收/过期 | 身份来自对应任务而非当前 head；质量、门禁、发布、报告状态分别保留；测量不可得不当成零；对比校验 profile/capture policy/level；不重复保存/交付不必要逐文件详情 |

报告是独立业务对象，不意味着报告里的任务、版本、证据、用量又各生成一份新的权威对象。B7 保存的是已核实事实的历史记录和读模型。


## 9. 对象之间的业务关系

~~~text
O01 能力契约 → 约束 O02 请求
                       │
            可受理时关联 O18 执行任务
                       │
O04 项目 → O15 输入 + O16 配置 + O17 条件 → O05 上下文/O06 源码
                       │
O27 索引规格/方案 → O29 构建 → O28 语义索引
                       │          └─包含 O07–O11 事实/绑定/证据
                       ▼
                 O22 发布裁决 → O21 版本 ← O23 快照引用
                                      │
O12 查询/O14 比较 → O30 求解 ──────────┘
                       ↓
                    O13 答案 → O03 交付

O19 预算约束执行；O20 服务承载任务和归属资源
O25 诊断 + 各方事实 → O26 报告
O24 维护计划/结果按真实引用保护处置历史与派生资产
~~~

该图不是强制流水线：help 可本地完成；普通 query 不启动索引生成；文件/文本能力可以没有语义图；prepare/export 不伪装成 daemon 已受理任务。

## 10. 避免对象混同

| 必须分开的对象 | 业务区别 |
|---|---|
| 能力契约 / 本机条件 | O01 定义支持，O17 说明当前条件，不互相证明 |
| 请求 / 任务 / 索引构建 | O02 表意图，O18 承载执行，O29 执行索引业务转换 |
| 索引 / 版本 / 快照 | O28 是知识内容，O21 固定已发布内容，O23 为可命名历史引用；当前快照名称可替换 |
| 查询规格 / 求解 / 答案 / 交付 | O12 定义问题，O30 求解，O13 承载事实，O03 表达实际交付 |
| 关系 / 出现 | O09 含不同子型；同一 from/to 的两次调用仍有两个现场 |
| 质量 / 发布 / 报告 | O11 是知识可靠边界，O22 是提交真相，O26 记录解释而不改写事实 |
| 比较代码 / 比较报告 | O14 的语义/多重性不同于 O26 的指标可比性 |
| 原始诊断 / 汇总 | O25 的位置、来源与次数不因归组消失；样例不等于总量 |
