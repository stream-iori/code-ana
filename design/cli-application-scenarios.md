# 产品场景六格与能力覆盖

状态：2026-11-08。用户已确认痛点及 15 个产品场景，采用“关注对象 × 期望结果”的六格。本文区分产品场景 P01–P15、支撑能力 C01–C31、业务对象 O01–O30；编号仅用于文档追溯，不增加 CLI 输出或产品公共 ID。CLI text/help 与运行边界已接入，实际验证范围见 docs/current-state.md。

## 1. 从需求形成产品场景

~~~text
已确认痛点 → 发生情境 → 用户要完成的任务 → 可验收结果
                                 ↓
                          产品场景 P01–P15
                                 ↓
                        用六格定位主要任务
                                 ↓
                    支撑能力 C01–C31 与业务规则
                                 ↓
                        DDD 责任边界与实现
~~~

场景按“业务动作＋业务对象”命名。一个产品场景可组合多个能力，一个能力可参与多个产品场景。命令、算法、进程、分页和编码不自动产生新场景；也不通过对象×动作的全排列证明需求完整。

## 2. 六格的维度与规则

| 维度 | 回答什么 | 取值与边界 |
|---|---|---|
| 关注对象 | 这次主要处理什么？ | 项目及分析成果：代码内容、关系、变化以及索引/答案/快照/报告；产品使用与运行：能力契约、任务、输入条件、环境、运行状态 |
| 期望结果 | 用户希望得到哪类结果？ | 查明现状：知道是什么/在哪里/怎样关联/已发生什么；形成判断：判断影响、适用性、可信程度或阻碍；改变状态：建立、更新、保存、清理、控制或恢复实际业务状态 |

两轴分别描述对象和预期效果，互不定义。以本次主要问题与验收结果归类：评估修改影响不会修改代码；审查差异不会产生该变化；更新索引则改变分析成果。辅助查询、缓存写入或返回回执不改变归属。描述基于所选静态模型，不等于实际运行观测。

| 关注对象 ↓ ／期望结果 → | 查明现状 | 形成判断 | 改变状态 |
|---|---|---|---|
| 项目及分析成果 | G11：熟悉项目结构 P04；定位业务实现 P05；追踪处理链路 P06；确认代码差异 P08；复查历史实现 P09 | G12：评估修改影响 P07；核验分析依据 P10 | G13：建立项目索引 P02；更新项目索引 P03；保全并交接成果 P13；清理过期分析资产 P14 |
| 产品使用与运行 | G21：发现可用能力 P01a；跟踪分析进展 P12a | G22：判断能力适用性 P01b；排查分析障碍 P11 | G23：控制分析过程 P12b；恢复分析可用性 P15 |

P01a/b 和 P12a/b 是复合场景中的业务子任务，不是新增痛点。P08 在 G11 中指确认前后差异；评估影响由 P07 承担，进一步判断业务是否符合需求由 agent 结合外部需求完成。P13 指生成并留存可复用快照/导出物，归 G13。help 在产品使用一侧仍承担核心价值；六格不是核心域/支撑域评级，也不是六个限界上下文。

### 2.1 六格对交付的要求

| 格子 | 主交付 | 必须可判断的边界 |
|---|---|---|
| G11 项目现状 | 可定位的内容、关系、结构或差异 | 身份/来源/范围、关系次数和方向、原文保真、未查全与未交付部分 |
| G12 项目判断 | 带依据的影响/适用性判断 | 确认与可能、模型假设、覆盖、未知项、计算及交付限制 |
| G13 成果改变 | 实际生成/更新/保存/清理结果 | 目标、实际范围、质量/门禁/提交、旧版保留、保护与未处理结果 |
| G21 产品现状 | 准确能力说明或当前运行事实 | 合法调用条件、观测范围、已知/未知、事件及正文交付范围 |
| G22 产品判断 | 适用条件、障碍及可继续条件 | 支持/就绪/本次答案充分分开；选择由 agent 基于事实推断，不输出默认 Next |
| G23 运行改变 | 控制请求与实际效果 | 受理/完成、实际终态、提交事实、失败/未完成及恢复边界 |

## 4. 支撑能力与输入/交付契约

C01–C31 保留为可复用能力和操作覆盖项，不再称为 31 个产品场景。它们承接 P 场景，引用 [业务对象](cli-business-objects.md)，并映射当前命令；同一能力可以服务多个场景。

| 业务能力 | 目的/输入与主对象 | 交付物或实际效果 | 关键验收 |
|---|---|---|---|
| C01 发现可用能力 | 为构造合法调用了解用途、语言和参数；O01 | 能力说明、输入约束、结果含义及限制 | help 与真实支持一致；静态支持、本机就绪和本次答案充分分别解释 |
| C02 检查分析条件 | 在分析前核对项目配置、输入与环境；O15/O16/O17 | 条件检查结论及必要生效值/来源 | 满足、缺失、不兼容、未验证分开；不执行目标构建，不承诺索引成功 |
| C03 准备分析输入 | 将选定工作区外部元数据/配置整理成分析输入；O15 | 输入清单及准备/降级结果 | 输入范围和可信程度明确；准备成功不冒充索引生效，不自动编译目标项目 |
| C04 建立项目索引 | 首次分析或让索引反映当前输入；项目、范围、政策；O27/O28/O29 | 实际可查询索引及范围、质量、启用结果 | 建立成功须实际生效；生成、门禁、提交分开，失败时说明旧版是否保留；报告失败不推翻已提交事实 |
| C05 定位程序实体 | 根据名称、签名、注释词或身份查找目标；O07 | 匹配实体及匹配依据、可复用目标 | 多候选、歧义和未查全明确；不能从受限集合断言唯一 |
| C06 查阅程序声明 | 已有明确实体，理解其定义；O07 | 对应语言的声明、必要属性及来源 | 目标正确、必要特征不丢；同一声明不重复 name/display/signature/metadata 多份表达 |
| C07 读取源码内容 | 阅读指定文件、声明或现场；当前/历史来源；O06 | 来源成立的原始源码片段 | 当前读取校验文件，历史读取用冻结内容；不互相回退；保留连续性、空行、缩进和末字符 |
| C08 检索工作区文本 | 根据文本/正则与路径范围找内容；O06 | 原文窗口、全部命中及位置 | 文本能力不依赖语义索引；重叠窗口可合并，命中不可丢；编码和计算缺口明确 |
| C09 检索源码注释 | 根据业务词找到注释内容；O08 | 注释正文、命中及已有声明链接 | 孤立注释不猜归属；保留链接证据，不附带源码窗口或内部 body_map |
| C10 查看程序结构 | 理解目标内部包含层级；O07/O09 | 声明包含结构及必要位置 | 只表达包含关系；内部声明、深度边界明确，不用辅助 facet 替代结构 |
| C11 查询程序关系 | 从主体、方向、关系种类找关联对象；O09 | 调用/引用/注解/类型/方法层级关系及依据 | 各子型独立验收：方向、次数、现场、环、meta 路径和确定程度不混用 |
| C12 定位调用现场 | 确定调用在源码中每次出现的位置；O09 | 每次调用、所属者、位置和已知目标/缺口 | 相同方法两次调用仍是两个现场；没有解析目标也不能丢现场 |
| C13 推断调用目标 | 根据明确调用现场判断静态目标；O10 | 原绑定、可能目标及必要证明 | 确认与候选分开；语言能力、算法假设和开放世界明确，不冒充运行事实 |
| C14 筛选实现候选 | 对类型/方法种子判断可能实现；O07 | 候选及可实例化判断、层级依据 | yes/unknown 等判断不混同；静态候选不当作实际运行实现 |
| C15 查找调用路径 | 对唯一起终点寻找连接；O09 | 一条已找到的有序调用路径及逐跳依据 | 不宣称全部路径；受限未找到不能证明不存在 |
| C16 汇总项目结构 | 对选定范围了解项目、模块、包或依赖分布；O04 | 按明确单位/口径形成的汇总答案 | 实体数、关系数与发生次数不混用；不把受限中间结果当全量总数 |
| C17 比较代码变化 | 对两个固定历史端点判断变化；O14 | 文件/声明/关系变化或静态可能影响 | 端点、模式、前后值/次数/side 明确；文件变化不是 patch，可能影响不是实际影响 |
| C18 保存历史快照 | 为复查/比较保留选定工作区或 Git 状态；O23 | 已保存快照及实际内容、引用结果 | files 不触发语义索引；analysis 组合 C04；同名可替换，实际引用与启用效果明确 |
| C19 查看快照目录 | 选择可复查或比较的已有历史端点；O23 | 快照身份、类型、来源与时间 | 返回可操作身份，不倾倒全部 manifest，不重新生成索引 |
| C20 解除快照引用 | 不再保留某个命名历史引用；O23 | 引用实际解除结果 | 不能承诺内容已立即回收，不影响仍受保护的资产 |
| C21 读取分析报告 | 理解指定任务已发生的分析；O26 | 原任务的质量、诊断、状态与已知用量 | 不从当前 head 猜原任务；未知不作零，不重新执行原分析 |
| C22 比较分析报告 | 对两个报告判断可比指标的变化；O26 | 可比性结论、指标前后值及差值 | project/profile/capture policy/level 等前提成立；不可比、缺失、未知明确 |
| C23 观察任务进展 | 理解指定任务当前/最终结果；O18 | 执行状态、事件及原业务结果/交付范围 | 执行、质量、发布、报告、交付分别成立；重放不重复，拿到终态不证明正文齐全 |
| C24 请求取消任务 | 对指定任务提出取消要求；O18 | 请求处理结果及可核实状态 | 受理不冒充已停止；已终态/提交不能假装撤销，必要时组合 C23 核实效果 |
| C25 检查服务状态 | 确认可连通服务及实际运行状态；O20 | 连通性响应或服务状态、活动任务数 | hello 只证明相应连通性；不证明语言/索引/FFI 全能力可用 |
| C26 排空分析服务 | 停止接纳新任务并处理既有任务；O20 | 排空请求、观察到的状态及完成边界 | draining 不冒充排空完成或进程已退出，未完成需如实呈现 |
| C27 请求取消服务任务 | 对该服务的任务批量提出取消要求；O20/O18 | 取消请求结果及当前服务事实 | 当前 daemon stop 调用 cancel_all，不宣称已关闭进程或撤销已提交版本 |
| C28 重启分析服务 | 取得重新启动并可连接的服务；O20 | 排空/等待/重连各阶段结果 | 当前为多步操作；失败阶段与待排空明确，不以请求发出冒充重启成功 |
| C29 预览资产处置 | 判断按当前条件可回收/清理什么；O24 | 候选、保护、未判定范围及预览计划 | gc 与 recover 各有子契约；预览不执行删除，不保证未来状态下计划不变 |
| C30 处置分析资产 | 回收无保护资产或清理已确认存储残留；O24 | 实际处理、未处理、失败及未知效果 | 执行时重新核对保护条件；recover 当前限 pending/orphans，不冒充通用进程修复 |
| C31 导出分析结果 | 在用户指定新路径留存业务结果；O03 | 新文件及实际写入结果 | 禁止覆盖，格式和写出失败明确；保存成功不证明原分析完整 |

## 6. 场景组合与实现边界

~~~text
发现适用能力 P01 → 建立索引 P02 → 熟悉结构 P04
                                        ↓
定位实现 P05 → 追踪链路 P06 → 评估影响 P07
                                        ↓
             agent 在产品外修改业务代码
                                        ↓
更新索引 P03 → 审查变化 P08 → 保全/交接 P13

按需贯穿：核验依据 P10、排查障碍 P11、跟踪/控制 P12
历史复查 P09、清理资产 P14、恢复可用性 P15 可独立触发
~~~

| 易混项 | 正确归属 |
|---|---|
| 发布索引 | P02/P03 或 analysis 快照的业务步骤和完成条件；候选生成不等于可用 |
| 首次/更新与 full/delta/reuse | 前者是用户情境，后者是完成它的执行策略 |
| 当前/历史、开放世界、strict、exact/CHA | 改变来源、判断含义或效果的部分属于业务契约；算法实现本身另论 |
| worker、SQL、RPC、缓存、序列化 | 技术机制，不单独构成产品场景或限界上下文 |
| 查询附带冻结页 | 原答案的交付机制，不让认知任务自动变成成果修改任务 |

六格不用于机械拆六个模块。DDD 边界按独立业务语言、规则、状态权威及一致性需求识别，见 [业务能力](cli-business-capabilities.md) 和 [实现边界分析](ddd-implementation-boundaries.md)。

## 7. 完整性与当前缺口

| 检查 | 结果/后续 |
|---|---|
| 痛点到场景 | 用户确认的需求由 P01–P15 承接，复合场景通过业务子任务进入六格 |
| 六格覆盖 | 15 个产品场景均有归属；P01/P12 跨格有明确子任务，辅助步骤不随意改变主格 |
| 场景到能力/入口 | C01–C31、35 条业务路径及 help/导出均可追溯；对象存在不要求独立 CRUD |
| 业务边界 | 产品提供分析依据，不修改目标业务源码、不自动执行目标构建；静态候选不等于运行事实 |
| 实现差距 | 当前 stop 为 cancel_all；若用户要停止服务，现行为不足，不能只改输出名称冒充完成 |
| 待验收 | 逐变体的 text/help、异常和任务链；实际 agent 调用/token/重试/误判效果 |
