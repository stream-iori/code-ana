# CLI 输出投影与验收设计

状态：CLI 协议 7 的公开投影设计；2026-11-09。已实现默认 text、显式 JSON 与 Markdown 文件导出。本文定义输出投影与验收矩阵；完整输入/输出契约、回执闭合与实施阶段以 [CLI 完整重构方案](cli-refactor-plan.md) 为准，避免保留第二套相互冲突的接口。

## 1. 从场景选择输出，不从内部 DTO 复制字段

~~~text
产品场景 P、六格中的主任务、输入与可验收交付物
       ↓
有类型的答案/操作结果 + 权威证据/状态
       ↓
按本次场景选择必要内容
       ↓
共享 header → content → 必要状态/限制/真实 cursor
       ↓
按所选格式计费并交付
~~~

| 已确认要求 | 目标行为 |
|---|---|
| agent 是用户 | 内容服务定位、推断和后续操作，不做另一套人类终端装饰层 |
| 默认 text | 目标数据/操作命令支持 --format text/json，JSON 只用于测试和结构化导出；report 的显式 Markdown 导出按主方案执行。支持通用格式参数 |
| 无默认 Next | 准确 help 定义能力/参数/结果；输出实际 cursor/原因，不拼未经验证的下一条命令 |
| 共享上下文 | 不要求一行一个结果；文件/所属者/主体/方向提升到最小共同 header |
| 原文保真 | 连续源码只在片段头给位置，不逐行加行号，不丢缩进/空行/字符 |
| 身份可操作 | 精确目标或必要公开 ID 可复用；有歧义时补范围，不随意缩短签名 |
| 内部字段按需 | revision/producer/profile/manifest/hash 普通查询默认不打印；历史操作、比较端点及诊断确有用途时显示 |
| 事实独立 | 语义、计算、交付、执行和发布分开，不用一个 OK/partial/truncated 包揽 |

### 1.1 按六格选择内容

六格/产品场景以 [场景文档](cli-application-scenarios.md) 为唯一来源；下文 C 编号指支撑能力，不指产品场景。六格决定主交付，下文 L1–L7 决定输出职责，不能混成同一套分类。

| 六格任务 | 输出首先回答什么 |
|---|---|
| G11 项目现状 | 对象、位置、原文/关系/变化是什么，查到哪里 |
| G12 项目判断 | 结论或可能范围是什么，依据、假设和未知是什么 |
| G13 成果改变 | 实际生成/启用/保存/清理了什么，哪些保留或未完成 |
| G21 产品现状 | 能力怎么用、观测到什么状态、哪些事实尚未知 |
| G22 产品判断 | 什么条件支持或阻碍使用，哪些信息足以供 agent 选择 |
| G23 运行改变 | 请求怎样处理，实际效果/终态/已提交事实是什么 |

公开投影归 B1，答案含义归 B3，构建质量归 B2，执行事实归 B5，实际提交/保护归 B6；不能让 renderer 重判业务事实。当前耦合及建议见 [DDD 实现边界](ddd-implementation-boundaries.md)。

## 2. 场景内独立分层

这些是输出职责，不是七步固定执行流水线，也不等于 DDD 的七个边界。

| 层 | 唯一问题 | 不得代替 |
|---|---|---|
| L1 内容投影 | 交付什么才足以服务用户目的？ | 不由存储字段或格式随意决定事实单位 |
| L2 身份上下文 | 结果是谁、在哪里、属于哪个必要范围/时间？ | 不用短名称隐去歧义，不把所有内部 ID 都倾倒出来 |
| L3 组织编码 | 怎样共享、排序、分块和引用原文？ | 不改关系次数，不把图压成单父树，不偷做统计 |
| L4 语义证据 | 输入/绑定/模型允许怎样的判断？ | 不根据执行成功或输出完整推断语义完整 |
| L5 执行与业务效果 | 请求、执行、门禁、提交、报告实际怎样？ | 不把取消请求、非零退出或报告失败当未发布 |
| L6 计算边界 | 查询/分析实际算到了哪里？ | 不把分页当计算停止，不把受限候选判断为唯一 |
| L7 交付边界 | 已有答案完整交付了多少？ | 不把已输出数量当全量，不因拿到终态就假定正文齐全 |

各层可独立选择分类维度，不预设四象限/九宫格。比如 L3 可按列表/树/图/路径/原文布局，L4 则按确认/可能/未知及覆盖范围判断；二者不能拼成业务总分类。

## 3. 查询正文结构

| 支撑能力及入口/模式 | header | content | 必须保持 |
|---|---|---|---|
| C05 定位程序实体：search-code | 文件 → 所属声明 | 位置、种类、可操作成员签名；需要时附匹配依据 | names/comments 区别、多候选、配置公开节点 |
| C05 定位程序实体／C06 查阅程序声明：resolve | 文件、范围、所属声明 | 对应语言的声明及必要特殊属性 | 已表达的 name/参数/返回值/修饰符不再逐字段重复；不能编造原声明 |
| C10 查看程序结构：structure | 文件 → 根声明 | 嵌套成员及位置 | 只表达包含关系，内部声明不可因压缩被裁掉 |
| C11 查询程序关系（调用）：calls | 查询主体/方向 → 实际调用者 → 文件 | 另一端及完整现场集合 | 方法关系可去重，现场次数保留 |
| C12 定位调用现场：call-sites | 文件 → 所属调用者 | 每次位置、现场、实际目标/缺口 | 相同目标两次调用仍两条；缺目标不丢现场 |
| C11 查询程序关系（引用）：references | 主体/方向 → 文件/所属者 | 位置、关系种类、另一端 | reads/writes/type/config 分开，incoming 不隐藏其他模块 |
| C07 读取源码内容：source | 文件 → 每个连续范围 | 原始源码 | 无逐行编号，不跨缺口拼接；长片段/多字节不丢头尾 |
| C08 检索工作区文本：search-text | 文件 → 连续窗口 | 原文与全部命中位置 | 合并重叠窗口只去重复原文，不删命中或改变行号含义 |
| C09 检索源码注释：search-comments | 文件 → 注释范围/种类 | 正文、命中及实际声明链接 | 孤立注释不猜归属，不附源码窗口，不输出 body_map |
| C11 查询程序关系（注解）：annotations | 被注解主体 → 直接现场 | 注解/属性，meta 时有序路径 | 直接/间接、未知属性和不同路径不合并 |
| C11 查询程序关系（类型）：type-relations | 主体/方向 → 实际起点/关系种类 | 另一端、必要位置/层数/证据 | 保留环、多个父关系与 possible 连线 |
| C11 查询程序关系（方法层级）：callable-relations | 主体/方向 → 方法关系 | 另一端、层数/必要依据 | overrides/implements_method 不混同 calls |
| C14 筛选实现候选：runtime-implementations | 种子、实例化筛选、模型假设 | 候选、yes/unknown、理由/层级依据 | 静态候选不是实际运行实现 |
| C13 推断调用目标：dispatch | 调用位置、算法与分析假设 | 原绑定、可能目标分别组织，附必要证明 | 方法证明/类型证明、确认/可能分开 |
| C15 查找调用路径：trace | 起终点/方向 | 有序跳转及逐跳现场/依据 | 当前一条找到的路径，不冒充全路径 |
| C16 汇总项目结构：overview | section、范围、单位 | project/modules/packages 分类；dependencies 源组→目标组/关系次数 | 不改计数口径，不交付受限中间总量 |
| 合法业务场景组合：pipeline | 最终结果类型的 header | 最终正文及必要上游缺口归属 | 不逐阶段倾倒全量结果，下游成功不洗掉上游缺口 |
| C17 比较代码变化：diff | 固定两端 → 模式 → 主体/文件 | 增删改、前后次数或带 side 的可能影响 | 四模式语义不同；files 不编造 patch |

source、文本和注释正文作为数据块交付，与真实状态行隔离；可采用足够长的代码围栏等明确边界。特殊名称、换行/控制字符按固定引用规则处理，不允许正文中的 status 样式文本被误当为终态。编码方案须在实现时冻结。

## 4. 操作、观测与帮助输出

| 支撑能力及入口 | 正文要回答什么 | 不能省略的例外 |
|---|---|---|
| C01 发现可用能力：help/version | 能力用途、必需输入、合法选项/互斥/前置、结果单位、限制及版本含义 | 静态支持不承诺本机就绪；不显示业务不支持的复用参数 |
| C03 准备分析输入／C04 建立项目索引：export/prepare/index | 本地准备、实际生成模式/范围、质量、门禁与发布各自结果 | 后台受理只有任务引用；复用仍有验证；已发布后异常必须保留发布事实 |
| C02 检查分析条件：doctor | 哪些条件满足、缺失、不兼容或未验证 | 不倾倒完整配置/bundle；相关生效值/来源按问题展示 |
| C18–C20 保存/查看/解除快照：snapshot/list/remove | 身份、files/analysis、来源、保存/引用变更结果 | 同名可替换；删除引用不等于立即回收图 |
| C23 观察任务进展／C24 请求取消任务：task status/watch/cancel | 当前/终态、控制请求、原结果交付范围 | 事件序列不是 cursor；取消不等于回滚；重连不重复正文 |
| C25–C28 检查/排空/取消服务任务/重启：daemon | 请求和实际服务状态 | stop 不凭命令名说进程已退出，restart 不是单原子动作 |
| C21 读取分析报告／C22 比较分析报告：report/--base | 原任务真相、诊断/资源已知范围、可比指标 | 不重跑原索引；Unknown 不写成 0；可比性失败不报零差异 |
| C29 预览资产处置／C30 处置分析资产：gc/recover | preview/execute、候选/保护/未判定及实际效果 | 不把预览当实际执行，不把 recover 当通用进程修复 |
| C25 检查服务状态：hello | 实际连通性响应 | 不证明索引、分析、FFI 全能力通过 |
| C31 导出分析结果：支持 --export 的任务 | 新路径、结果格式与实际写入状态 | 禁止覆盖；写出失败与原业务结果分开 |

保留现行退出码含义：0 成功、1 错误、2 参数错误、3 strict 拒绝、124 超时、130 取消。退出码不替代正文中的实际业务事实：0 不自动表示语义完整，非零不自动表示未发布；报告/输出失败与已提交可以同时成立。

## 5. 身份、顺序与压缩边界

| 内容 | 压缩规则 |
|---|---|
| 文件/主体/范围 | 最小共同 header 共享；跨 world/module/scope 不错误合并 |
| 公开目标 | 仅在明确可重建/唯一时省前缀；否则保留必要 selector/ID，不能从内部整数键导航 |
| SQL 别名/metadata | 仅移除已知 SQL 辅助字段与重复声明字段，不递归删除生产者扩展内的同名键；未知值包括 null/false/空串保持 |
| 源码块 | 只合并同一捕获来源、同一上下文的真实连续字节范围；保持空行、缩进、换行和字符边界 |
| 关系/出现/路径 | 同义字段可压缩；多重性、环、方向、路径顺序和证据差异不删 |
| 证明 | 可共享前缀，不能仅剩“有依据”而丢决定确认/可能的证据 |
| 聚合 | 查询决定聚合，renderer 不暗自把明细变次数；单位、分组、范围和样本性质明确 |
| 稳定顺序 | 先确定语义排序/分组，再冻结/分页；renderer 不临时重排造成漏项/重复 |
| 状态 | 按主方案使用 end 闭合当前回执；只有编码器核实正常基线时才省略语义/计算/交付例外，不由缺少警告推断完整 |
| 进度 | 默认不刷 queued/running 或重复任务 ID；进度不替代必要业务终态 |

### 分页与不完整答案

~~~text
results: 1–20 / 38
cursor: <实际游标>
~~~

总数仅在已完成枚举时输出。计算受限时不输出分母，JSON 的 delivery.total 为 null；冻结结果的内部条数仅用于续页。

~~~text
semantic: partial
  comment_inputs_unavailable: app-b/MAIN
~~~

~~~text
computation: limited
  max_work reached
~~~

语义缺口、计算停止和页未交付分开。不打印 Next；help 解释如何使用 cursor/预算等实际能力。

### 索引与控制

~~~text
index: published
semantic: partial
  classpath_unavailable: app/MAIN
~~~

~~~text
index: published
report: failed
error: REPORT_WRITE_FAILED: <实际原因>
~~~

~~~text
cancel: requested
task: <实际任务ID>
~~~

以上索引/控制主体有必要显式状态；默认成功静默规则不能抹掉“是否生效”。样例不提供未经验证的恢复命令，也不假定 4096 等固定重试额度足够。

## 8. 验收设计


| 六格及产品场景 | 主要验收 |
|---|---|
| G11：P04/P05/P06/P08/P09 | 定位、原文、关系/路径/差异及固定来源，查询和交付边界明确 |
| G12：P07/P10 | 判断依据、静态可能、模型假设、覆盖和未知项，不把空结果升级为否定结论 |
| G13：P02/P03/P13/P14 | 索引真实生效、成果留存与资产实际处置，门禁/提交/保护分别成立 |
| G21：P01a/P12a | 合法能力说明、当前运行事实及事件/正文交付范围 |
| G22：P01b/P11 | 适用条件、障碍与未知项可解释，agent 能据此自行选择 |
| G23：P12b/P15 | 控制/恢复实际效果，保留已提交事实，不把受理当完成 |

以下 C 编号核对支撑能力与变体，不维护第二套产品场景：

| 支撑能力 | 必测正常情况 | 必测边界 |
|---|---|---|
| C01 发现可用能力 | 按 help 构造各命令有效请求 | 无关复用参数、非法组合、静态支持/环境不可用、语言 unsupported |
| C02–C04 条件/输入/索引 | 已准备输入、--prepare、full/delta/reuse、partial 发布 | 缺依赖/损坏/超限/取消；删除/零输出；strict；期望基线冲突；提交前中后；报告/ack 失败 |
| C05–C17 代码问题答案 | 全部查询家族、文件/语义路径、四种 diff 和聚合模式 | 同名/跨 module/world、多现场/环/meta 多路径、外部无源码、开放世界、受限唯一性/聚合/否定结论 |
