# 业务能力与领域边界

状态：CLI text 输出改造的领域基线，2026-11-08。业务规则来自用户确认的产品定位、当前代码和契约；本轮在现有进程/crate 内落实输入、投影和用例路由；不把业务边界数量映射成部署数量。

## 1. 产品价值与设计顺序

agent 是唯一用户。产品价值包括：发现可用能力、构造合法请求、建立可信索引、求解代码问题、正确理解结果并采取后续行动。

~~~text
产品价值/用户目的 → 业务能力与规则边界
                           ↓
                输入/触发、交付物与验收契约
                           ↓
                   引用业务对象/业务策略
                           ↓
                  工作流、实现与输出验证
~~~

| 已确认原则 | 含义 |
|---|---|
| help 是核心能力 | 能力发现、参数约束、输入输出含义和限制必须支持 agent 正确推断 |
| 默认 text | JSON 仅用于测试和结构化导出，不以 JSON 作为 text 排版模板 |
| 事实先于建议 | 默认不输出 Next；输出实际目标、限制和 cursor，agent 根据准确 help 决定动作 |
| 按任务评价成本 | 同时看 token、额外调用、重试和误判，不能只压缩单条结果 |
| 保留可靠边界 | 空结果、语义缺口、计算停止、交付未完、执行失败、实际发布分别成立 |

## 2. 业务能力与权威边界

| 边界 | 战略归类与能力 | 权威事实 | 不得越界 |
|---|---|---|---|
| B1 Agent 交互契约 | 核心；能力发现、合法调用、结果解释 | help/参数/结果及交付语义应如何准确呈现 | 不改写 B2/B3 的绑定、次数或证据，不把支持写成已就绪 |
| B2 索引生成与更新 | 核心；规格、构建、语义索引及质量 | 固定输入/基线能生成哪些实体、关系、绑定、覆盖及实际处理范围 | 不用通用任务替代构建规则，不把生成结束当发布成功 |
| B3 索引/源码查询与演变 | 核心；定位、关联、推导、原文、聚合、差异 | 固定上下文中答案是什么，依据和计算边界是什么 | 不隐式补分析/编译，不把候选、样本和单条路径说成穷尽答案 |
| B4 输入与环境就绪 | 支撑；准备、配置、依赖、工具链验证 | 输入是否可信、本机满足哪些条件、可信降级还是失败 | 清单存在不等于可用；准备成功不等于索引成功 |
| B5 任务执行与控制 | 支撑；准入、排队、资源、取消、服务控制 | 受理/执行/终态、事件、控制意图和已核实用量 | 请求不等于完成；取消不推翻持久提交；未知用量不写成零 |
| B6 发布与历史保全 | 支撑；提交、冻结历史、快照引用、维护 | 门禁/实际提交、版本引用、保护根和实际维护效果 | 不重新解释语言语义；发布后异常不假装未发布 |
| B7 报告与诊断 | 支撑；记录、归组、比较与解释 | 对应任务的报告、可比指标、诊断次数/省略量 | 不从当前 head 猜原任务身份，不因报告失败改变质量或发布 |

这些是模型责任边界，不是七个进程、crate 或已经定稿的七个限界上下文。gRPC、SQLite、clap、JSON codec、文件 IO 属于实现机制；复用通用库不降低其承载的核心交互价值。

### 2.1 六格怎样调用业务边界

| 六格中的任务 | 需要的责任协作 |
|---|---|
| G11 项目现状／G12 项目判断 | B3 提供事实和判断依据，B6 提供固定来源，B1 交付；B4/B7 提供必要输入/解释 |
| G13 分析成果改变 | B2 构建知识，B6 裁决实际提交、引用与处置；B4 准备输入，B5 承载任务，B1/B7 交付与解释 |
| G21 产品现状／G22 产品判断 | B1 消费各域真实能力，B4 给出就绪事实，B5/B7 给出执行和诊断事实；适用选择由 agent 推断 |
| G23 运行改变 | B5 处理控制，B6 提供提交/保护与恢复权威；B1 准确呈现请求和实际效果 |

实现边界按业务语言、规则所有者、状态权威和一致性识别，不按六格数目拆服务。当前证据、候选上下文与渐进改造见 [DDD 实现边界分析](ddd-implementation-boundaries.md)。

## 3. 核心价值链：目标、交付物与手段

| 视角 | 索引生成与更新 | 索引/源码查询 |
|---|---|---|
| 用户目标 | 让 agent 能对选定项目开展可信分析 | 让 agent 获得足以理解实现、关系或变化的可靠答案 |
| 可验收交付物 | 索引能力/help、已生效可查询索引、实际构建/质量与效果回执 | 查询能力/help、定位/原文/关系/候选/统计/差异答案及证据边界 |
| 手段与策略 | 准备/捕获、full/delta/reuse、提取/替换/校验/发布；具体机制另论 | 消歧、遍历、派发、检索、聚合、比较、pipeline；具体机制另论 |

此表是同一场景的因果链对照，不是三类并列场景，也不是正交分类轴。目标不是交付物名称，交付物不是实现动作；输入请求单列为前置条件，不能一并归入产品交付物。

能改变答案含义或业务效果的策略必须进入交付契约，例如 exact/CHA、开放世界、当前/历史和 strict。SQL、worker、RPC 等机制通常不需要进入默认输出。文件/文本查询不必有语义索引。

交付物可以作为场景中心，但要附用户目的、输入/触发、可用性、证据和验收边界；仅有“源码片段/报告”等类型名不构成完整场景。

产品场景统一采用“动作＋业务对象＋必要限定”的动宾短语。已确认的 P01–P15 场景及“关注对象×期望结果”六格以 [场景目录](cli-application-scenarios.md) 为唯一来源；C01–C31 是支撑能力，O01–O30 是业务对象。六格定位用户任务，B1–B7 定位规则和状态权威，二者不是一一对应关系。不能用 worker/SQL/pipeline/分页等实现或交付方式代替业务目的。

## 4. 核心/支撑的协作

~~~text
Agent ←→ B1 能力/请求/结果契约
             │
     ┌───────┴────────────────┐
     ▼                        ▼
B4 输入/就绪 → B2 索引构建   B3 查询求解
                    │          ▲
              候选内容/质量    │ 固定索引/源码/比较端点
                    ▼          │
              B6 发布/历史 ────┘

B5 承载执行、预算和控制，并与 B6 裁决取消/提交
B7 汇集各方真实事实形成报告/诊断，经 B1 交付
~~~

| 易混事实 | 规则归属 |
|---|---|
| 产品支持 / 本机就绪 / 本次答案充分 | B2/B3 规则、B4/B5 条件、本次证据各自提供真相，B1 准确解释 |
| 质量 / strict / 发布 | B2/B3 产生质量；发布场景由 B6 按策略裁决；查询 strict 消费质量和完整性事实，不改写它们 |
| 取消 / durable commit | B5 处理控制意图；B6 的实际提交有权威；超时/断连不能撤销已成立事实 |
| 本地 prepare / daemon index | 当前准备在 CLI 本地，不经过 SubmitTask，二者不是跨进程单事务 |
| 索引内容 / 知识版本 | O28 描述能回答什么；O21/O22 描述哪个内容真实提交、如何引用保护；无需复制物理图 |
| 比较代码 / 比较报告 | B3 判断代码语义变化；B7 校验报告指标可比性，不能共用一套变化含义 |
| 原文 / 位置 | B3 定义读取语义，B4/B6 提供实际来源；B1 不伪造连续片段或吞空行 |

## 5. 重构前差距与设计回应

| 代码证据 | 影响 | 改造责任 |
|---|---|---|
| direction 解析接受 both，但 query preflight 仅允许 overview 使用 | help 诱导无效请求 | B1 与 B3 真实参数契约保持一致 |
| QueryArgs 大范围复用 | 参数出现不等于业务支持，部分无关项可能被忽略 | 按能力呈现参数，不按 struct 复用暴露 |
| help/握手/LanguagePolicy/preflight 分散定义能力 | 支持、协议能力、语言能力与就绪性易混 | 建立可核对的能力契约，分别消费实际事实 |
| wire JSON 带出 SQL 辅助列和 metadata | 内容重复，agent 承担理解成本 | 公开投影不自动包含存储列 |
| 非零退出也可能已发布 | 错误恢复可能重复操作 | 执行/门禁/发布/报告/交付独立表达 |
