# 优先重构待办

状态：本轮 CLI 范围 R1–R3 已完成；2026-11-09。执行阶段及目标样例见 [CLI 完整方案](../design/cli-refactor-plan.md) 和 [执行清单](cli-implementation-plan.md)。本文件维护三项优先工作的执行状态。产品场景与六格见 [场景目录](../design/cli-application-scenarios.md)，规则归属及完整代码分析见 [DDD 实现边界](../design/ddd-implementation-boundaries.md)。

## 执行顺序

| 顺序 | 工作 | 要解决的问题 | 完成标准 |
|---|---|---|---|
| R1 | 统一公开能力契约 | help、参数解析、预检和能力声明不一致，agent 容易构造无效请求 | 能力说明、合法输入、真实支持与实际效果一致 |
| R2 | 分离业务结果、公开投影和输出编码 | 存储字段进入展示，内容重复，预算与 JSON 编码耦合 | 默认 text 按场景交付必要内容，保留业务语义，按最终格式计费 |
| R3 | 收紧操作路由与领域服务职责 | 查询服务同时承接查询、维护、历史写操作和报告 | 应用层组合用例，各领域服务负责自己的规则和状态 |

## R1：统一公开能力契约

设计依据：[公开能力契约问题](../design/ddd-implementation-boundaries.md)。

- [x] 按命令与语言明确用途、必需输入、合法选项、互斥/前置、结果单位及副作用，处理无关复用参数。
- [x] 按 S1 落实目标参数名、文本 pipeline、格式/详情/导出选项和接入版本。
- [x] 各业务域拥有真实规则，交互层统一消费可核对的能力契约，供 help、预检和能力声明保持一致。
- [x] 区分静态支持、本机就绪与本次答案充分，不将 unsupported 呈现为零结果。
- [x] 按 S5 补齐 stop/restart 等待与实例确认，使 help 和回执一致；未确认退出不能返回 stopped。
- [x] 验收：根据 help 能构造合法请求；非法组合、语言限制和未就绪情况得到准确反馈；不添加默认 Next。

## R2：分离业务结果、公开投影和输出编码

设计依据：[投影与编码边界](../design/ddd-implementation-boundaries.md)、[text 输出设计](../design/cli-output-design.md)。

- [x] 明确类型化业务结果与公开内容的边界，按产品场景、六格和结果单位选择必要字段。
- [x] 去除同一声明的多份同义表达和存储辅助别名；必要的生产者扩展保留，不按同值盲删。
- [x] 文件、所属者和范围提升到共同 header；连续源码保留原文，不逐行重复编号。
- [x] 默认 text；JSON 仅用于测试和结构化导出。内容投影与编码分开，预算按最终所选格式计算。
- [x] 按 S2–S4 落实目标复用、end/framing、基线/例外、只凭 cursor 续页与原子导出。
- [x] 验收：关系与现场次数、方向、候选/确认、证据和未知状态保持；长源码、多字节、分页及终态交付完整性保持。
- [x] 以代表性 agent 任务核对重复内容和额外调用是否减少，不以单条输出变短替代任务效果验收。

具体内容与压缩约定以 [text 输出设计](../design/cli-output-design.md) 为准。

## R3：收紧操作路由与领域服务职责

设计依据：[操作路由与服务职责](../design/ddd-implementation-boundaries.md)。

- [x] 将通用操作路由放到明确的应用用例调度层，组合查询、历史、维护、就绪和报告服务。
- [x] 查询服务负责固定上下文中的求解；资产命令、就绪判断和报告交给所属业务服务。
- [x] 随职责调整复用查询、索引、任务窄端口，移除 QueryService 的维护/报告等调用；保持原子存储适配。完整 Store 的逐域收窄属于后续演进，不计作本轮全部完成。
- [x] 验收：现有 35 条业务路径及 help/导出映射保持；图/文本查询、历史续页、快照、报告、GC 和恢复行为保持。
- [x] 验收：查询核心继续不依赖存储实现；发布事务、引用保护、取消与实际提交边界保持。
