# 注释检索收敛到 symbol 级关联

状态：已完成（2026-11-08，本机自建 fixture、产品与实际分发范围）。汇总证据：`target/java17-plan-check/joint-receipt.json`；不签跨平台、完整语义或容量性能放行。

## 1. 目标与边界

将注释查询收敛为：

```text
注释关键词
    ↓
命中注释正文、精确位置、所属声明 symbol
    ↓
agent 按 symbol 读取完整方法／函数源码
```

| 项目             | 改造后行为                                           |
| ---------------- | ---------------------------------------------------- |
| 默认上下 5 行    | 删除整个注释源码窗口机制，不改成默认 0 行            |
| 上下文配置与参数 | 删除注释专用 TOML 配置、CLI 参数、RPC 字段和冻结参数 |
| 相邻语句关联     | 删除 `leading_statement`、`trailing_statement`       |
| 声明关联         | 保留 `documents`、`enclosing_callable`               |
| 函数内部注释     | 继续索引正文、保存位置并关联所属函数                 |
| 文件头及孤立注释 | 继续检索，保留文件和位置，不猜测函数                 |
| 完整函数源码     | 使用现有 `source` 能力按需读取，搜索接口不自动附带   |

不新增代码块关联，不修改通用文本搜索的上下文功能。

## 2. 实现改造

### 查询、配置与公开接口

- 删除注释专用 `context_before/context_after`、`CommentContext`、默认值归一化和范围校验；清理仅为这些参数存在的中间类型与调用链。
- 删除 `[query.comments]` 展示配置以及 CLI `--context-before/--context-after`；旧配置和旧参数明确报错，提示删除。
- protobuf 删除字段 49、50，保留对应字段编号与名称为 `reserved`，禁止复用。
- `CommentMatch` 删除 `source: SourceSnippet`；保留注释正文、来源身份、原始范围、命中映射及声明关联。
- 删除源码窗口计算、片段复制和对应输出计费。原正文到源码的命中映射仍保留必要的捕获源码读取、hash 校验、预算和取消检查。
- `search-code --in comments` 继续按声明去重并保留不同注释命中；pipeline 仍通过声明链接导航。
- 清理 prepared 配置中仅服务于注释展示参数的摘要例外；保留与其他配置、输入完整性有关的验证。

### 三语言关联生产

- Java、Rust、Python 同步停止生产前置／行尾语句关系，删除专用的相邻语句扫描、空白判断及辅助缓存。
- 保留语言规则产生的文档归属和最近有效 callable 归属。
- 保留用于区分嵌套函数、lambda、局部类及初始化块的作用域结构，禁止因删除语句扫描而误挂到外层函数。
- 无公开 symbol 的 callable 继续保留原有作用域定位范围；这属于归属证据，不恢复相邻语句／局部代码块关联，也不伪造 symbol。
- 删除仅供已移除关系使用的 `heuristic` 分支；保留声明关系的 `language_rule` 依据及规则版本。

### 存储与交付

- 公共关系枚举、GRA1 校验、存储写入、只读投影和 DDL 仅接受 `documents/enclosing_callable`。
- 保留声明关联使用的目标范围、精确声明引用、source/world 校验及独立注释表／FTS。
- 修改 DDL 源文件与生成器后重新生成紧凑 schema，禁止仅手改生成文件。
- 更新三语言 producer／关联规则身份，确保旧结果不会被误复用。
- 更新 fixture 预期关联数量和功能断言；历史验收回执及原性能数据保持原义，不覆盖或重新标注。

## 3. 兼容与源码读取

以下版本以本计划制定时的仓库状态为基线；实施前核对版本占用，若已被其他变更使用，则在当前值上递增并同步全部生产／消费端。

| 边界               | 处理方式                                                                         |
| ------------------ | -------------------------------------------------------------------------------- |
| CLI / daemon       | daemon 协议 4 → 5；注释能力标识更新为 `comment-search-v2`                        |
| worker / 公共模型  | worker 23 → 24、graph model 5 → 6、GraphSemantics 27 → 28                        |
| 图库               | 物理 schema 12 → 13、逻辑 schema 35 → 36                                         |
| Java 分析协议      | analysis request/result 12 → 13，同步生产与消费端                                |
| javac 模型 / C ABI | 本次不修改脱离模型形状、compiler 帧及 ABI 函数签名，保持 v51 / batch 2 / C ABI 4 |
| 旧图库             | 查询及增量返回重建要求，执行 `index --full`；不原地迁移                          |
| 旧分页游标         | 明确拒绝并提示重新查询，不兼容旧 `CommentMatch` 冻结结果                         |
| 安装与分发         | Rust、三语言 worker 和 Java SDK 成套更新，禁止新旧混装                           |

完整源码读取沿用现有行为：

- 按命中的公开 symbol 读取整个声明范围；长函数允许按现有源码分块机制返回，agent 需要读取全部分块。
- 查询和后续源码读取使用同一 revision，避免搜索命中与源码版本漂移。
- 普通源码入口继续校验当前文件 hash；需要历史内容时使用显式历史入口读取捕获 blob。
- 无 symbol 的注释保持文件定位，不自动扩大到整个文件，也不猜测所属函数。

## 4. 验证与验收

先验证 Java fixture，再验证 Rust、Python 和公共链路。

| 场景                               | 验收标准                                                 |
| ---------------------------------- | -------------------------------------------------------- |
| 方法文档、函数内部注释             | 关键词仍能找到正确 symbol                                |
| 同一函数多条注释                   | 函数结果去重，全部不同命中证据保留                       |
| 嵌套函数、lambda、局部类、初始化块 | 保持作用域边界，不错误投影到外层函数                     |
| 文件头、类型／字段文档、孤立注释   | 保持原有声明或文件定位                                   |
| Unicode、CRLF、emoji、多行注释     | 正文、位置及命中映射正确                                 |
| 搜索输出                           | 不再包含源码窗口及上下文参数                             |
| 局部关联删除                       | 三语言输出、图库及公开结果均无两种语句关系               |
| 完整源码读取                       | 长函数、分块、多字节字符、历史 revision 均能完整读取     |
| 旧接口与数据                       | 旧参数／配置、旧 daemon、旧图库和旧游标按约定明确拒绝    |
| 生命周期                           | 注释独改、清空、删除、重命名、full/delta、冻结分页无残留 |
| 通用文本检索                       | 原有文本上下文参数及输出保持有效                         |

执行现有 Java fixture、Rust 完整门禁、Python fixture、Native 生命周期与产品回归，以及受影响的分发回归；包含生成 DDL 检查。不新增性能测量，不把历史测量作为本次改造的性能证明。

## 5. 交付顺序与完成条件

1. **契约与模型**：确定新输出形状、版本和旧数据拒绝行为，同步文档与 fixture 预期。
2. **生产与存储**：三语言删除语句关联，更新校验、DDL、规则身份与增量门禁。
3. **查询与配置**：删除窗口、参数和配置，贯通 CLI／RPC／pipeline／冻结分页。
4. **验证与分发**：按上述顺序完成检查，确认完整函数读取和旧版本拒绝行为。

完成时同步现行配置、查询、存储、语言模块、协议和当前实现文档，并更新原注释计划及联合路线图中的现行规则。删除失效测试，补充行为验收，保留历史回执。

最终交付标准：**注释可检索、symbol 可导航、完整函数可读取；查询不再生成上下文窗口，也不再计算相邻语句关联。**
