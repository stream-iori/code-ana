# Java 17 支持与验证实施计划

状态：已完成（2026-11-08，本机自建 fixture、JVM／Native 产品与实际分发范围）。汇总证据：`target/java17-plan-check/joint-receipt.json`；按用户要求不做真实项目测量或专项优化，不签跨平台或容量性能放行。

参考提交：Anatomist `7787f2d29d85a8d6db511f28c7f4cbe7f03928f6`（2026-11-03）。选择性借鉴导航验收场景、JDK 选择证据和未变复用校验，不整体迁移其实现。

## 1. 目标与边界

在保留 Java 8 能力的基础上，打通 Java 17 的配置、工具链、javac 模型、图库、增量和分发链路。

```text
显式目标版本与工具链
    → 冻结输入及身份
    → 对应版本 javac 子进程
    → 独立模型与图事实
    → fixture、产品与分发验收
```

| 项目          | 本次实施范围                                                              |
| ------------- | ------------------------------------------------------------------------- |
| 目标版本      | 支持 Java 8、17；Java 25 目标及混合版本模块继续拒绝                       |
| 分析后端      | javac 唯一后端；禁用处理器，不生成目标项目业务字节码                      |
| Native 工具链 | 保持 GraalVM Java 25、G1 和现有 isolate 生命周期                          |
| 上游借鉴      | 导航场景、JDK 选择证据、未变复用校验；不引入 JavaParser 或 catalog solver |
| 性能          | 仅使用本仓库 fixture 验收；不安排真实项目测量或专项性能优化                   |
| 当前阶段      | 联合实施中，尚未完成产品链路与分发验收                                      |

原固定为 8 的产品入口、Session、捕获模块和 Captured 模型已改为消费冻结目标；javac 内部 API 的共享源码分别由 Java 8／17 编译并独立打包。实际完成范围与剩余验收见 current-state。

## 2. 功能改造

| 子系统       | 实施要求                                                                                                                                                |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 配置与工具链 | 显式接受目标版本 8、17；从已登记工具链中匹配对应版本，多个候选要求显式别名。实际 JDK 主版本必须与目标一致，不增加环境回退                               |
| 输入冻结     | 将目标版本、实际 JDK 版本、规范化路径、工具链内容摘要和编译桥身份纳入冻结输入及语义身份；Java 17 覆盖 `lib/modules`、`ct.sym`、`jmods` 等编译和平台输入 |
| 版本传递     | 清理 Rust、worker、Java Session、模块模型和框架配置中固定为 8 的值；统一消费冻结的目标版本，禁止下游自行探测                                            |
| 编译桥       | 公共扫描、模型和传输逻辑共享；javac 内部 API 适配按 Java 8、17 分开编译和打包，运行时按已验证目标版本选择对应桥                                         |
| Java 17 适配 | 验证注释扫描、AST 遍历、模式变量、record 成员及构造器、sealed 类型等模型交付；修复实际缺失，不另写布尔作用域或泛型推导替代 javac                        |
| 调用与引用   | 保留 javac 的精确绑定、泛型签名及合成成员身份；不可解析或歧义目标保留未知，不按名称、参数个数猜边                                                       |
| 增量与缓存   | 工具链、桥或语义身份变化禁止复用旧分析；保留现有内容哈希和任务内懒加载目录共享                                                                          |
| 诊断         | doctor、索引报告及错误展示目标版本、实际版本、工具链别名/路径、摘要及选择失败原因；版本不匹配在分析前拒绝                                               |
| 生命周期     | worker 复用身份包含目标版本、工具链和桥身份，避免跨版本误复用；取消、预算、故障换进程及旧 head 保留沿用现有规则                                         |

编译桥按版本隔离 javac 内部 API，不复制整套提取器。构建显式提供 Java 8、17 JDK；SDK 缺桥、桥版本错误或摘要不符时直接拒绝。

不照搬上游低版本 catalog 回退，也不把路径、文件大小、修改时间当作当前 JDK 内容的完整证明。现有工具链内容哈希继续保留。

## 3. 接口、兼容与分发

- 在 `JavaConfig` 新增显式目标版本字段；Java 分析请求同步携带该字段，生产入口拒绝缺失值。
- `BuildContext.source_version`、producer 和能力信息反映实际目标；统一清理固定 `javac-java8` 的身份描述。
- SDK manifest 登记支持版本及对应桥文件、摘要；Native/JVM 构建、安装、验收脚本和分发包同步校验。
- worker 协议、Java analysis request/result 和 SDK manifest 格式在实施时从当时版本递增，同步全部生产与消费端；拒绝旧请求和混装 SDK。
- 保持公开 symbol ID 规则及公共图行形状；本计划不要求修改 daemon、C ABI、图库物理 schema、compiler batch 或 detached model 格式。新增语义通过 adapter/模型规则身份使旧分析失效。
- 新 SDK 首次分析要求全量重建，不迁移旧 revision；兼容的历史图继续只读查询。
- 与其他 todo 计划串行核对版本占用，不预先占用具体版本号。更新现行配置、Java worker、构建分发及验证边界文档；来源清单单独登记本次借鉴提交，不整体替换既有参考基线。

## 4. 测试与完成标准

先补本仓库自建 Java 17 fixture，再执行产品和分发回归。上游 fixture 只用于设计参考，不作为本仓库验收输入。

| 场景              | 验收标准                                                                                                |
| ----------------- | ------------------------------------------------------------------------------------------------------- |
| 工具链选择        | 8/17 正确匹配；缺失、歧义、错版本、缺桥、坏摘要明确失败                                                 |
| JDK API           | `List.of/copyOf`、`String.isBlank/formatted`、`Stream.toList` 精确指向目标 JDK 成员                     |
| 模式变量          | 三元、取反、`&&`、`&#124;&#124;`、提前返回及同名遮蔽；合法引用正确绑定，非法引用不产生假边 |
| record            | 隐式、紧凑、显式 canonical 构造器；委托、重载、嵌套 record、accessor 和方法引用目标正确                 |
| 回调与泛型        | 泛型 collect、record 方法引用、返回值方法引用、构造器内回调赋值；精确目标正确，歧义保留未知             |
| 其他 Java 17 语法 | sealed 类型、文本块、switch 表达式可交付；声明、引用、位置和注释归属正确                                |
| 增量与复用        | 全量、修改、删除、未变复用结果符合真值；源码不变而 JDK/桥改变时重新分析                                 |
| 资源与故障        | 超时、取消、预算耗尽和编译器崩溃不发布候选；原 head 保留，累计回执正确                                  |
| 双后端            | JVM 与 Native 使用相同 fixture 真值，分别验证模型和公开查询                                             |
| 回归与分发        | Java 8 无退化；Java fixture 优先，再跑 Rust 门禁、受影响的 Python/混合链路、Native 生命周期和实际包回归 |

不以“索引成功”代替导航真值检查。失败日志、修复前后差异和最终回执均保留；fixture、真实项目和正式放行分别记录。

## 5. 验收范围与交付顺序

### 验收范围调整

按用户最新决定，仅用本仓库 fixture 验收，不安排真实 Java 17 项目测量或专项性能优化。
JDK 17 使用 SDKMAN 匹配；与注释收敛合并交付，协议统一升级一次。

### 交付顺序

1. 核对当前版本、协议和测试入口，建立 Java 17 fixture 真值。
2. 完成目标版本传递、工具链校验及分版本编译桥。
3. 修复模型交付、图提取和增量中实际暴露的问题。
4. 完成双后端、Java 8 回归、生命周期和分发验收。
5. 完成注释收敛的联合 fixture 与受影响分发回归。
6. 更新现行文档、来源和回执，逐项登记通过范围及未完成边界。

完成条件：上述功能、产品链路与分发门禁有当前产物的实际证据，未通过项明确列出。fixture、产品与分发验收仅认证实际覆盖范围，不声明真实项目、跨平台或容量性能放行。
