## 2. Fixture 准备与产品执行分离

| 步骤 | 执行者/路径 | 保存证据 |
|---|---|---|

| 冻结 | 产品捕获已有文件和 EffectiveConfig | manifest、source snapshot、profile、字段来源 |
| 分析 | CLI → daemon → Rust host → 实际 Java shared library → 目标 JDK javac（D17 验证后） | task/attempt、IPC 完成清单、事实/coverage/diagnostic |
| 发布 | 接收校验、门禁、对象持久化、catalog 提交 | expected/actual revision、提交结果、五维状态 |
| 查询 | 普通/历史入口、pipeline、diff | typed 记录、终止证据、输出字节和退出码 |
| 故障检查 | 可控注入点触发失败或进程退出 | 注入点、旧/新 head、重启恢复结果、剩余引用 |

构建建议夹具设置可观测的构建入口或执行记录：目标构建/处理器调用次数为 0；禁用处理器且不生成业务字节码的 javac parse/analyze 单独记录；外部显式准备完成后再提交新任务。不能用“预编译后测试通过”掩盖产品偷偷构建。

## 4. 全量/增量比较方法

```text
同一目标输入 S、同一 semantic profile P
    +-- full(S,P) -----------------------------> F
    +-- baseline(S_prev,P_prev) + cold delta ---> C
    +-- 允许时：已确认会话 + hot delta --------> H

分别发布并导出规范化事实/证据；比较 F == C [== H]
```

| 保留 | 仅可排除 |
|---|---|
| 声明、调用点多重性、绑定状态、类型/框架关系、依赖桶 | task/attempt ID、时间戳/耗时等非语义运行字段 |
| owner/world/scope/profile、输入身份、语义范围 | 存储 rowid、物理布局、非语义迭代顺序 |
| coverage 状态/原因、诊断总数、provenance 规则/依据 | 各次执行生成的发布外壳 ID；须保留其所指 source/profile 身份 |

规范化规则应版本化；不能为了让测试通过删掉 unresolved、诊断、来源或重复 occurrence。热 worker 已进入验收，必须与冷路径比较完整事实。

## 5. 发布故障注入矩阵

| 注入时点 | 预期 head | 重启后的判定 |
|---|---|---|
| ResultEnd 前/校验失败/门禁拒绝 | 旧版 | attempt 失败/中断，无发布 |
| blobs/facts 持久化失败 | 旧版 | 失败候选保留恢复信息或可确认归属后清理 |
| revision 文件就位、catalog 前 | 旧版 | 未发布孤儿对象，不自动补发 |
| CAS 不匹配 | 已存在的较新版本 | conflict，旧 delta 不重贴 |
| catalog 事务未完成时退出 | 以恢复后 catalog 为准 | 明确已提交或未提交，不能猜 |
| catalog 已提交、响应前退出 | 新版 | GetTask 返回同一提交，不再分析 |
| 发布后报告/清理失败 | 新版 | 后处理 failed/pending，published=true |

进程崩溃注入与真正断电/文件系统耐久性验证分别记录；仅通过 kill 测试不能宣称覆盖所有断电行为。

## 6. 测量与默认值冻结

| 度量 | 必须记录 |
|---|---|
| 环境 | commit、fixture/hash/规模参数、OS/架构、CPU/内存、Rust/JDK/native-image/依赖版本 |
| 启动/查询 | daemon/worker 冷启动、握手、单命令/pipeline 时间；声明重复次数和离散情况 |
| 索引 | 捕获、基线导出、Java 分析、编码/IPC、候选校验/复制/提交耗时 |
| 内存 | daemon 和 worker 进程树同时刻 RSS、采样间隔、观测峰值；host/原生库同进程不重复求和，目标 JDK 子进程另计；不加各进程独立峰值 |
| 磁盘 | 输入 blobs、candidate、backup 字节、发布库、GC 前后占用、编译器编码暂存和签名缓存；磁盘满路径单测 |
| 故障/预算 | 配置的上限、实际触发原因、取消响应时间、释放后资源、head/引用状态 |

P0 形成一张版本化参数表：消息/帧大小、队列容量、任务/输出/中间记录预算、订阅宽限期、事件/结果保留期、取消宽限期、重规划次数、worker/全局内存和空闲策略。数值由 fixture 测量与实现限制决定，不将示例 2 GiB/8 MiB/600 秒直接当承诺。

内存预约、RSS 采样后主动终止与 OS 级硬限制分别记录；采样存在延迟和超调，不能把 TOML 上限或一次观测峰值当成精确的进程硬限制。

每份阶段报告记录“通过/失败/不适用/未执行”、对应断言、实际结果、复现命令、日志与产物引用；功能证据和性能记录分开，fixture 通过不等于真实项目容量达标。
