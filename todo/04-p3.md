# P3：Rust、多语言与后续扩展

**Java 主线完成后再进入 Rust。公共模型从 P0 保留 world/language，Rust 能力逐项声明，semantic 请求不能悄悄降成 syntax。**

依据：[Rust worker](../docs/modules/rust-worker.md)、[配置](../docs/configuration.md)、[交付范围](../docs/delivery.md)。

## Rust 工作包

| ID | 工作 | 依赖 | 产出与验收 |
|---|---|---|---|
| P3-01 | rust-analyzer 依赖/API 原型 | P2 与公共契约 | 锁版本、AnalyzerFacade、真实构建产物/宏边界与能力矩阵；无法实现的能力明确拒绝 |
| P3-02 | syntax worker | P3-01 | 声明、范围、属性、模块语法、未绑定出现、cfg 未求值条件和来源；不声称名称已解析 |
| P3-03 | semantic/world | P3-02 | 已验证 crate graph/toolchain/target/features/cfg、跨 crate 绑定、类型/trait/impl 事实与缺口 |
| P3-04 | 宏与 Rust 查询策略 | P3-03 | 展开来源、静态/possible 目标、有界遍历；缺过程宏产物只建议外部准备 |
| P3-05 | Rust 增量与混合发布 | P3-03/04 | 失败查找传播、分区复用、统一 revision/coverage 与 owner 清理 |
| P3-06 | 能力与故障验收 | P3-01～05 | T05 及 Rust 对应通用场景通过，公开支持子集 |

- [ ] Rust 语言 worker 与 Java 的 Rust host 明确区分，使用同一公共 IPC/Fact IR 接口，保持独立能力描述符。
- [ ] 发现只读 manifest/lockfile/既有元数据；crate graph 不足时返回 BuildAdvice，不运行 build.rs/过程宏/目标构建补齐。
- [ ] target 平台和 Cargo lib/bin/test target 分开；host 解析为真实平台身份；同物理文件多 crate/world 有独立 SymbolKey。
- [ ] syntax 模式不接受需要 semantic 求值的 world 配置，semantic 不足时披露或拒绝，不改请求模式。
- [ ] 声明宏/过程宏各列支持矩阵；生成文本与真实源文件区分，有 expansion 链和原始锚点。
- [ ] trait object 候选附开放世界与预算；泛型首版保存源码约束，不枚举全部单态实例。
- [ ] full/冷增量/允许的热复用保持事实与证据等价，新增声明使失败查找成功必须重算。
- [ ] 混合项目原子发布所有分区及项目 coverage；只改 Rust features 可复用有证明的 Java 分区，关闭语言/world 清除当前 owners。
- [ ] 无证据不按同名建立跨语言关系；显式跨语言证据若支持，必须有独立类型与来源。

## Rust fixture 验收

| fixture | 必须验证 |
|---|---|
| 两 crate workspace | 跨 crate 函数、模块身份、外部符号 |
| 同文件两个 features/world | 条件互斥不合并，不错误去重 |
| trait 静态/动态调用 | resolved 与 possible 区分，有 proof/限制 |
| 声明宏与缺过程宏产物 | 来源清楚、缺口可见、无自动执行 |
| 新增声明/更改 cfg/依赖 | 失败查找与环境失效传播，full/delta 等价 |
| Java + Rust | 配置命名空间隔离、单语言改动复用、整体发布和关闭清理 |
