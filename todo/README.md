同一阶段的独立工作包可以分别推进；任务表中的依赖是合入/验收前置条件，不代表必须同时开发。先稳定共享契约，避免各模块自行发明身份和状态。

P0-04a 从第 1 步验证原生库协调 javac 的真实链路，模型/JDK/桥兼容问题必须在 P0-02/03 冻结前反馈。P0-04b 才验完整事实与冷增量。执行方案失败时调整 javac 边界，不退回其他解析器。每个工作包可再拆成小提交；不按未经测量的工时承诺排期。

## 执行约定

- 实现前读取该工作包引用的设计；改变设计须更新对应 `docs/` 与决策记录。
- Java 代码统一放在 `lang-adaptor/`；原生库按 `.sdkmanrc` 使用 GraalVM JDK 25，编译器桥的目标字节码兼容单独验证；禁止 JNI。
- 产品不自动构建目标项目；fixture 准备可以显式编译，准备命令与产品命令分开记录。
- 每个工作包交付实现、相关验收证据、能力/错误说明；不能只有接口空壳。
- 测量参数在 P0 后冻结；示例 TOML 中的预算值不视为已验证默认值。
- 当前方案沿用设计的 Java 优先与独立产品边界，无 Anatomist 兼容门禁。
