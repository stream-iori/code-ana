# P2：完善 Java 能力和数据生命周期

> Rust 先行、Java mock 的执行状态见 [07-rust-first.md](07-rust-first.md)。本页涉及真实 javac/native 的验收不因 mock 通过而完成。

本轮已补 Rust files/text、查询邻接、配置冻结、报告、标注与迁移/GC 恢复；P2-03 diff 按用户要求暂缓，已有命令仅做回归。下列复合任务仍按真实 Java 与规模化门禁验收，不因 mock 测试整体勾选。

**目标：在 P1 可信闭环上交付高级查询、历史/diff、报告、人工标注和完整恢复/GC。先固定对象引用，再开放删除。**

## P2-01：高级查询

- [ ] 实现 annotations、type-relations、callable-relations、runtime-implementations；明确 Java 注解查询与人工 annotation 的区别。
- [ ] 实现 dispatch 和有界 trace；只用已发布的类型/方法/facet 事实，输出候选依据、开放世界和截断原因。
- [ ] 实现 overview，摘要/样例不能支持否定结论；外部声明没有源码时说明具体原因。
- [ ] 完善多 subject/source 连续行页与证据 replacement；所有记录保持稳定公共排序。
- [ ] 实现独立 search-text；files/text 无语言配置也可用，不自动补索引、不扩大历史捕获；text_only/exclude 按冻结策略执行。
- [ ] 为批量邻接与反向关系建定向索引；先测瓶颈再优化，不为每条边单独往返数据库。

验收：深度/状态/实体/输出预算分别可触发；达到深度上限不宣称无更长路径；possible 关系不伪装为已绑定或运行时观测。

## P2-02：历史与 source

- [ ] Git ref 解析一次固定 commit；WORKTREE 保存当次清单和字节，检测捕获变化，不宣称整个目录的 OS 原子快照。
- [ ] FILES snapshot 不启动语言 worker/构建；ANALYSIS snapshot 复用或请求符合 profile 的 revision。
- [ ] Repository/Project 共享历史，Checkout/IndexTarget 隔离活动入口；linked worktree 有专门夹具。
- [ ] snapshot 保存 profile/EffectiveConfig/捕获策略；按精确历史 ID 读取不需要当前工作区、JDK 或 adapter 可执行文件。
- [ ] 历史 source 仅从 hash 校验后的 blob 读取；普通 source 继续校验当前文件，不隐式回退冻结内容。
- [ ] 历史语义缺产物只给指定 commit/profile 的准备建议；不能套用无法证明匹配的当前 JAR 或生成源码。
- [ ] 生成声明提供原始来源；生成文本明确标记，无法获得时返回能力限制。

验收：捕获后改文件/切分支/删除当前 classpath，历史结果不变；未捕获 TEST 不解释为 TEST 无变化。

## P2-03：diff、影响分析和冻结续页

- [ ] 分别实现 files、declarations、relations、impact；各自返回 completeness/limits/reasons，不共用一个模糊的完整标记。
- [ ] 两端先固定 snapshot/revision/profile 与读者引用；声明按逻辑身份/依据匹配，调用点比较保留多重集。
- [ ] 位置移动不机械变成语义变更；重命名推断附依据，不把同名自动配对当成已证实。
- [ ] impact 分别在两端捕获图遍历；显示 scope 不截断中间路径，可能派发不写成事实关系变化。
- [ ] 生成 ComparisonResultId，冻结 rows/evidence/options/endpoints；暂存/排序有 spill 字节和磁盘预算。
- [ ] 续页只读冻结结果；cursor 绑定结果及选项，结果过期明确失败；只读续页不准备索引或触发自动 GC。

验收：首屏后修改源码/移动分支/发布新版本，余页内容和证据保持一致；两端 profile 不同仅限制受影响能力，不抹掉可证明的文件变化。

## P2-04：诊断、报告、doctor

- [ ] doctor 按语言/module/world 解释配置值、FieldOrigin、generation、能力、完整性与恢复建议。
- [ ] DiagnosticCollector 记录事件总数、分组、样例和省略数；样例截断不改变质量判断。
- [ ] 实现 off/basic/full 报告，保存本次提交返回身份、五维状态、计时和可选文件级基线；预算/保留策略独立于事实 GC。
- [ ] report read/compare 只读取保存报告；profile/扫描策略/级别不可比时拒绝，不重跑索引补报告。
- [ ] 自动报告大小/数量有界；显式导出新路径且禁止覆盖，不纳入自动报告 GC。
- [ ] 发布后报告写失败仍显示真实 revision/published=true，按已冻结退出码返回失败；清理失败单列 pending。

验收：报告失败、报告过期、full 基线缺失、门禁拒绝均可单独解释；阶段计时存在重叠时不简单求和。

## P2-05：人工标注

- [ ] 独立存正文、来源、内容版本和 anchor；派生 binding 单独记录目标 revision/world、symbol、状态及依据。
- [ ] 提供创建/修改/读取与明确锚定；定义 bound/ambiguous/orphaned/unavailable，不自动按同名或跨 world 重绑。
- [ ] 查询/整条 pipeline 固定 annotation revision，图 revision 不随正文编辑改变。
- [ ] 重建只更新派生绑定；声明删除/重命名、历史图删除或 schema 演进失败时正文与 annotation ID 保留。
- [ ] 默认历史查询返回能证明绑定到所选图版本的内容并披露 annotation revision；完整正文历史回溯另作可选需求。

验收：标注编辑与查询并发不混版本；重建、GC、重命名、多 world 歧义均不会丢正文或误绑定。

## P2-06：GC、恢复和数据演进

```text
活动/命名入口、pin、reader、build、未过期 comparison
                         |
                     保护根遍历
                         |
              preview -> 删除前再核对 -> 执行
                         |
          有保护引用就保留；容量超限也不强删
```

- [ ] 将 open_read、捕获/build 引用、snapshot、comparison 和 GC 纳入同一引用协调机制。
- [ ] preview 只给计划/恢复需求；执行前重新检查引用；分批删除可恢复，失败登记 pending。
- [ ] 恢复区分未提交 candidate、已持久化孤儿 revision、已提交但未响应任务；catalog 是唯一发布裁决。
- [ ] 重启后确认进程身份/启动时间与归属后才解除失效 lease 或清理 worker；不处理外部 Agent/人类构建进程。
- [ ] schema 演进使用新 candidate/影子 catalog 或事务策略；演进失败保留原产物和恢复入口，不能先删后建。
- [ ] graph GC 不删除 annotation 正文；报告清理、缓存清理有独立策略和计量。

验收：reader/query/index/diff 与 GC 竞争不丢对象；全部对象被保护时清楚报告容量目标未达。逐提交窗口故障、磁盘满、清理失败和未来 schema 失败均有恢复记录。

## P2-07：环境增量与可选缓存/并行

- [ ] 扩展 JDK/JAR 内容、classpath 顺序、adapter/rule、Lombok/框架配置、模块/源码根变化的失效闭包。
- [ ] 扩基线重规划有最大次数/工作量，过大退全量；CAS 冲突重新固定基线，不能重用旧 delta 偷渡提交。
- [ ] 压缩 BaselineFacts 之前先以 P1 足够基线作为正确性对照，逐种依赖验证不能漏失败查找。
- [ ] 先测重复分析成本，再评估 NoCode 模块签名 + 独立声明目录；保留 SOURCE 注解、泛型和来源，不作为构建成功证明。
- [ ] 签名键覆盖源码、有序依赖、JDK、桥/模型/规则和 Lombok 配置；不完整/损坏/冲突回封存源码，在途引用 pin；启停缓存的事实和证据等价。
- [ ] 有界并行采用稳定任务图/消费序号；线程数、输入到达顺序变化不改变候选数组、诊断与事实；默认仍串行，性能与默认开启另验。
- [ ] 单线程/多线程采用相同输入和资源预算，记录同 PID/generation 的真实重叠、取消与失败；无性能放行证据不宣称提速。
- [ ] 仅在测量有收益时启用热会话；key 包含已 PublishAck 的 revision/profile/输入身份，预算与空闲策略可回收。
- [ ] 同输入/profile 比较 full、冷增量、热增量的事实多重集和证据；缓存丢弃只能影响性能。

验收：环境变化、插件失败/关闭、OOM、取消、重规划耗尽和发布冲突下仍满足等价或明确失败保旧版。
