## P0-01：fixture 与复用审计

- [ ] 建 `java-basic`：声明树、构造器、重载/继承/接口、相同方法对重复调用、未解析调用、外部符号、非 ASCII/补充平面字符与换行。
- [ ] 建最小 `java-frameworks`：Lombok 签名模型、Spring Java/XML、SOFA 引用；每个 producer 至少包含启用、关闭和失败预期。
- [ ] 建增量编辑序列：修改方法体、新增声明使失败查找成功、删除声明/资源；每一步保留完整目标输入。
- [ ] 提供独立 fixture manifest：来源 commit/hash、目标 Java 版本、编译准备步骤、依赖摘要、预期 owner/事实/coverage/provenance。
- [ ] 审计 javac/model/extract/framework/incremental/StagedGraphStore；列“复用/改写/舍弃”，记录 JDBC、查询层和配置层依赖的解除方式。
- [ ] 固定 Anatomist `2dfc7977cb03095d14894f069ff30985551457b1`；审计 core/java、core/javac、compiler worker、JavaModelExtractor、框架 overlay 与 ASM；记录文件 hash/许可证/依赖。
- [ ] 提前验证原生库的模型/ASM/框架可达性与目标 JDK 编译器桥；不引入 JavaParser/SymbolSolver 或兼容 AST，执行 P0-04a 后再批量搬源码。
- [ ] basic 增补泛型实例化、SAM/lambda/方法引用、嵌套二进制名、源码注解、已选目标但局部类型缺失、歧义/不可访问与大量诊断。

验收：两次独立准备产生相同受控输入摘要；正确性预期能从 fixture 源码/资源说明推导。准备可显式构建 fixture，产品路径的构建执行次数必须为 0。

## P0-02：身份、模型、事实与协议

```text
领域模型（model）
    +-- CLI-daemon protobuf：TaskService
    +-- daemon-worker protobuf：控制 / baseline / Fact IR
    +-- Java C ABI：字节缓冲 / handle / 状态码

三层分别版本化；D17 候选另有编译器内部协议及独立 Java 模型版本。语义身份采用独立规范化，不能 hash protobuf 编码。
```

- [ ] 根据 P0-04a 反馈定义独立 Java 模型：类型/声明/实例化类型、二进制名、注解、UTF-16 span；公共 IR/facets 保留查询所需信息，编译器对象不越界。
- [ ] 冻结 declaration_resolved/evidence_complete/binding_origin 的独立语义与恢复预算；诊断保存 code、phase、位置、归属和重复次数。
- [ ] 定义 JavaCompilerPlan 三范围、物理模块/发布标签映射和内部协议终态；context 完成不代替项目 ResultEnd。
- [ ] 冻结 Repository/Project/Checkout/IndexTarget、LogicalSymbol/World/Symbol、Occurrence/Fact、snapshot/profile/revision 的组成与等价规则。
- [ ] 冻结 owner 元组、声明唯一归属、producer 扩展方式；空替换与替换为空分开；替换同步覆盖依赖、诊断、coverage 和 provenance。
- [ ] 为 Fact IR 全部事实组建立类型和最小夹具；存储支持按需落地，但接收器不能静默忽略必需事实段或 facet。
- [ ] 固定路径、Unicode、大小写、摘要算法/版本、UTF-8 字节范围与行范围规则；定义 Java UTF-16 坐标转换和非 UTF-8 输入的拒绝/显式转换策略。
- [ ] 冻结 enumeration/semantic/limits、stage/subject/page 归属、五维任务结果；区分 unresolved/unknown/not_requested/unsupported。
- [ ] 建 TaskService、worker、Java 配置和 Fact IR 的 `.proto` 草案；presence、UNSPECIFIED、reserved、未知值处理和必需能力协商有夹具。
- [ ] 拟定 selector、文本输出版本、pipeline JSON、错误码/退出码、quiet、完整记录预算；复杂操作可暂不可用，不能省略公共证据契约。
- [ ] 定义 Java facets 支持派发所需的类型层级、方法覆盖、接收者/候选依据；用 P0-05 的回放修正后冻结。

验收：Rust/Java 对同一消息得到相同类型化内容与规范化身份；重复调用仍为两个 occurrence。故意删 coverage、混 owner/world、输入未知必需 facet 时拒绝。

## P0-03：显式配置、BuildContext 与输入捕获

- [ ] 实现项目/用户 schema 与来源结构的最小通路；未知键/版本/错误类型拒绝，Java 必须显式启用；未安装语言返回 unsupported。
- [ ] 固定配置快照时点：接受/准备时保存项目配置字节和用户 generation，排队后不能重新解释；discover 后解析 auto 并冻结 EffectiveConfig。
- [ ] 验证标量 presence、一般数组整体替换、范围交集/exclude 并集、模块精确匹配、用户上限超限拒绝。
- [ ] 分离 ConfigDigest、SemanticConfigDigest、CapturePolicyDigest 与 query/execution policy；注释/报告变化不无故重建。
- [ ] 确定目标版本/执行 JDK 与 adapter 构建 JDK 的关系；auto 仅选用户登记的唯一匹配工具链，错误环境变量不得改变结果；Java semantic 拒绝 vm_classpath=false。
- [ ] 先完成 plain 显式模块发现；Maven 只读发现接口与已有 metadata 交付格式在此阶段定稿，完整实现放 P1-02。
- [ ] 冻结 SourceSnapshot/manifest/blob、补充输入封存和变化重试机制；源码、XML、配置、生成输入、JAR 与目标 JDK 产物可追溯。
- [ ] 定 BuildArtifactManifest 候选契约：源码/控制输入、工具链、构建选项、模块/world、产物内容摘要、生成者及可信程度；缺证明时不可将产物视为已验证。
- [ ] 定 BuildAdvice：用户 checkout 的 cwd、argv、缺失输入、预期产物、影响和重试；无可靠命令时只报告缺失信息。

验收：捕获后改工作区不影响分析；普通 source 必须报 hash 不匹配。禁用建议仍保留缺口；整个发现/分析路径不启动目标项目构建或 annotation processor。

## P0-04：javac 执行边界与真实分析

### P0-04a：提前验证执行可行性

前置仅为 P0-01 的最小源码与手工冻结输入，不依赖完整配置/存储实现；结果反馈 P0-02/03。

- [ ] 保留 D13 的 Java 25 原生库 + Rust C ABI host，验证 D17 的目标 JDK 子进程与最小编译器桥；只运行禁用处理器、无业务字节码生成的 parse/analyze。
- [ ] 实际共享库启动桥并接收独立 Java 模型，确认所需 API、资源、协议与错误转换；候选 Java 8/17/25 逐版本记录通过/失败/未执行。
- [ ] 编译器桥与原生库分开构建，验证 Java 8 兼容字节码及跨 JDK API；不把桥规则当作全工程降级 Java 版本。
- [ ] 验证缺/错 JDK、host/编译器崩溃、交换中取消与父进程退出后的子进程回收；输出进程树和实际内存记录。
- [ ] 形成 D17 决策与支持版本清单；失败调整 javac 执行设计，影响已确认 D13 时提出具体方案，不恢复其他解析器。

验收：不是仅能启动 java；实际 native 链路产生带位置/绑定/诊断的独立模型，取消和终止可回收。未通过前不能冻结最终执行协议或承诺支持矩阵。

### P0-04b：实际事实和 FFI 生命周期

前置为 04a 结论、P0-02/03 的最小模型/配置契约。

- [ ] 按实际复用需要拆 `analysis-core`、`native-bridge`、框架模块；native bridge 只做入口、生命周期、编码。
- [ ] 修正依赖引入后的 native 构建 classpath，固定依赖/工具链/插件；生成共享库、C header、绑定和 build/ABI manifest。
- [ ] 建立装载前平台/产物核对与稳定 ABI bootstrap；不能先调用不兼容函数再检查版本。
- [ ] 实现 session/input_chunk/seal/analyze_start/poll/read_result/cancel/release/close/publish_ack 代表通路；输入/输出块、handle 数量都有上限。
- [ ] 专用线程进入 isolate；逐线程 attach；Java 异常转状态/诊断，Rust panic 不跨 ABI；所有终止路径释放资源。
- [ ] 移植最小 javac/独立模型/绑定/提取与内存 fact sink；原生运行 basic、框架代表例和冷增量例，不能仅 JVM 测试通过。
- [ ] 区分完整语义输入与发布/owner 范围；先使用足够封存源码供 javac 分析，BaselineFacts 不直接当 classpath；MAIN/TEST 有最小夹具。
- [ ] 冷增量先导入足够基线，包含失败查找桶和未变事实；验证“基线减 owner 加新事实”逻辑视图；收到 PublishAck 后才允许会话复用。
- [ ] 测多轮分析/取消/错误/释放，记录 worker 进程树同时刻 RSS、基线、javac 上下文、模型、复制、编码/解码和临时磁盘；故障结束不导致 daemon 退出。

验收：实际共享库产生的 full 与冷 delta 在同输入/profile 下规范化相等；native 崩溃/OOM/卡死由 worker 边界隔离。Hello、JVM 单测或手工 delta 均不满足此退出条件。

## P0-05：原子发布与查询回放

- [ ] 用手写 Fact IR 建 candidate 与最小 SQLite schema；export_baseline、apply_delta、定向查询端口明确。
- [ ] 实现 ResultBegin/Chunk/End 接收与校验：seq、长度、计数、摘要、身份、owner、引用和零事实 owner coverage。
- [ ] full 新库、delta 通过 SQLite backup 创建私有副本；处理 sidecar、关闭写连接，持久化对象后进入 catalog CAS 事务。
- [ ] 将 head 更新、revision 注册、提交身份关联放入同一 catalog 提交裁决；任务注册在接收请求时已持久化。
- [ ] open_read 在同一协调区内选择身份并登记引用；resolve/call-sites/source 只读此上下文。
- [ ] 用重复调用与复杂 Java 派发夹具检验 Fact IR 足够；缺事实回 P0-02/04 补充，不在普通查询中调用 worker。
- [ ] 注入接收/落盘/移动/catalog 提交前后故障，验证旧 head、孤儿对象、提交后丢响应三种状态。
- [ ] 测 backup 耗时、复制字节、候选磁盘峰值、长读者成本；记录 D03 是否继续采用不可变 generation。

验收：没有 ResultEnd 或校验失败的候选不可见；旧 reader 跨发布仍读旧版；catalog 已提交但响应丢失能查回同一 revision；取消不能抹掉已提交事实。

## P0-06：任务服务、IPC 与进程控制

- [ ] 实现 Handshake、SubmitTask、WatchTask、GetTask、CancelTask 原型；RPC 状态与任务结果分离。
- [ ] 请求 ID + 规范化 payload hash 做幂等；同 ID 异内容拒绝；登记/提交状态持久化，重启不重复执行已提交任务。
- [ ] 用户级单实例注册、动态 loopback endpoint、所属用户访问校验、进程启动身份、版本拒绝和手动 drain/restart 通路。
- [ ] daemon 启动独立 Java host；用专用继承管道承载长度前缀 protobuf，stdout/stderr 为日志；不把 FFI 当 IPC。
- [ ] 握手、Discover、Analyze、ReplanNeeded、结果块、PublishAck；帧大小、队列、deadline 与慢消费者策略明确。
- [ ] 区分任务 deadline/RPC deadline、提交后的取消/订阅关闭；设置 Submit 到 Watch 的宽限期和事件保留窗口。
- [ ] 登记 javac 子进程归属、启动身份和退出状态；整个进程树预约资源；终止 host 后验证编译器与临时文件已回收。
- [ ] 全局 worker 预约与同 IndexTarget 串行；CPU/SQLite 工作不阻塞服务和取消入口；只终止能证明归属的 worker。

验收：双 CLI 冷启动只有一个 daemon；流中断/重复请求/取消与提交竞争均返回真实发布状态；worker 崩溃后 daemon 继续服务其他请求。
