# 注释索引与代码关联开发计划

状态：待开发。本文仅记录已讨论的方案与验收要求；所有复选项均为待办，不代表已经实现或通过测试。

总排期见 [架构整改与注释索引联合开发计划](architecture-and-comments-roadmap.md)。本文保留注释功能的详细规则；架构任务、硬依赖和阶段门禁由总计划维护。实施顺序为：必要架构拆分 → 本文注释功能 → 后续架构整改。

P0 对应总计划 C0，在 A0 基线建立后即可开展；P1 对应 C1，须等待 A2 统一索引编排和 A3 配置与查询接入边界验收。P2—P4 依次对应 C2—C4，不等待后续 A4—A7。P5 改为各阶段持续同步文档，P4/C4 做最终核对。

## 1. 目标与确定规则

- [ ] 支持 Java、Rust、Python 标准注释及文档注释的索引。
- [ ] 引入 jieba-rs，支持通过中文关键词检索注释，导航到相关代码和所属方法。
- [ ] 注释、关联、全文索引随代码 revision 原子发布，支持删除、增量、历史查询和冻结分页。
- [ ] 周边代码默认显示**注释开始行之前 5 行、结束行之后 5 行**，包含完整注释；文件边界自动裁剪。
- [ ] 展示窗口可以跨方法边界；语义关联仍遵守作用域，不能把窗口中的其他方法误认为注释所属方法。
- [ ] 首期支持关键词全文检索；任意子串、错字容错、项目自定义词典及相关性排序留待后续。
- [ ] 语义关联要求显式启用对应语言；FILES-only 场景继续使用现有文本搜索。

```text
冻结源码
   ↓
语言侧：注释提取 + 声明归属 + 附近语句关联
   ↓
Rust：统一分词 → 注释表 / 关联表 / FTS5
   ↓
校验 candidate → 原子发布 revision
   ↓
关键词查询
   ├─ 命中注释
   ├─ 上下文代码：默认上下各 5 行
   └─ 所属方法：公开身份、声明位置
```

## 2. 配置与查询接口

### 上下文配置

项目 `.code-ana/config.toml` 新增：

```toml
[query.comments]
context_before = 5
context_after = 5
```

- [ ] 两项分别接受 `0..=100` 的整数，缺省均为 5；负数、超范围及未知字段明确报错。
- [ ] 查询增加 `--context-before N`、`--context-after N`，分别覆盖配置；显式 `0` 必须与未提供区分。
- [ ] 优先级：显式请求参数 > 项目配置 > 内置默认值。
- [ ] 当前部分 TOML 查询默认值尚未接入执行，新增配置必须贯通配置加载、请求归一化和查询执行，不能只增加 schema。
- [ ] 上下文配置只影响展示，不进入语义索引指纹，不触发重新索引。
- [ ] 首页查询冻结实际上下文参数；修改配置后续页仍使用原参数。
- [ ] 保持已有 `search-text --context` 行为。

### 查询入口

以下为待实现接口：

```sh
codeana search-comments "库存不足"
codeana search-comments "库存不足" --context-before 3 --context-after 8
codeana search-code "库存不足" --in names,comments
```

- [ ] `search-comments` 返回注释、命中证据、源码窗口、可选所属声明及附近语句关联。
- [ ] `search-code --in names|comments|names,comments` 默认 `names`，保持已有行为；注释命中投影为可导航声明。
- [ ] 文件级或无法关联声明的注释仍可由 `search-comments` 返回。
- [ ] 方法结果按实体去重，保留不同注释命中；支持继续进入 `resolve/source`。
- [ ] 首期沿用公开 ID 稳定排序；注释结果按路径、位置、world、公开 ID 稳定排序。
- [ ] 新的注释查询输入作为普通关键词处理，转义后构造 FTS 表达式；已有名称搜索语法保持。
- [ ] 新增类型化请求、结果及能力标签，贯通 CLI、gRPC、pipeline 和分页；旧服务不支持时明确拒绝。

## 3. 提取、存储与生命周期

### 语言提取和关联

| 语言 | 首期规则 | 实现边界 |
|---|---|---|
| Java | Javadoc、行注释、块注释 | 扩展现有 javac 桥及模型；保持目标 Java 8，不引入其他解析后端 |
| Rust | 内外文档注释、普通注释、字面量 `doc` 属性 | 复用 rust-analyzer 语法树；不执行宏或外部文档包含 |
| Python | `#`、标准位置的模块/类/函数 docstring | 复用现有 AST 并补词法提取；普通字符串不作为注释 |

- [ ] 分别保存 `documents`、`enclosing_callable`、`leading_statement`、`trailing_statement` 关系。
- [ ] 文档归属按语言规则；方法归属按最近有效作用域。
- [ ] 行尾注释关联同块同行前一语句；前置注释仅在同块、无空行及其他有效 token 隔断时关联下一语句。
- [ ] 位置推断标记 `heuristic`；无法确定时保留文件定位，不猜测。
- [ ] 附近语句范围作为关联证据保存；源码展示始终使用配置行数，不自动扩大为整个语句块。
- [ ] 文件头、嵌套函数、lambda、局部类、初始化块分别处理；无公开实体时保留范围，不伪造节点。
- [ ] 注释提取及关联覆盖缺口独立披露，不能因类型绑定缺失直接丢弃可提取注释。
- [ ] 通过语言词法规则处理字符串伪注释、转义及多行边界，不采用全文件正则抽取。

### 存储与分词

| 对象（建议名称） | 内容 | 职责 |
|---|---|---|
| `graph_comments` | 公开 ID、来源身份、源码 hash、种类、原始范围、正文、分词文本及位置映射 | 保存注释事实 |
| `graph_comment_links` | 注释引用、关系类型、可选声明引用、目标源码范围、关联依据与规则版本 | 保存声明归属及附近语句关联 |
| `comment_terms` | external-content FTS5，指向注释表 | 全文检索 |
| `project_meta` | 分词器、词典、归一化及关联规则版本或摘要 | 复用与兼容性验证 |

- [ ] 复用文件字典、节点整数引用和逻辑只读投影；内部整数主键不输出。
- [ ] 注释正文只保存一次，不复制到方法 metadata。
- [ ] 原始注释及周边代码从捕获 blob 读取；去标记后的正文保留到原始源码的位置映射。
- [ ] 新增字节范围使用 UTF-8 半开区间；公开行列遵守现有 UTF-16 契约。
- [ ] 注释关联限制在同一 source instance/world 内。
- [ ] 注释公开 ID 在固定 revision 内可重现；不承诺位置变化后的跨 revision 身份稳定。
- [ ] 普通语句只保存关联范围，首期不持久化完整 AST。
- [ ] Rust 侧统一封装 jieba-rs：建索引使用搜索模式，查询使用默认分词模式，HMM 固定开启；查询词默认 AND。
- [ ] 英文及代码标识符保留完整词并拆分驼峰、下划线；查询与索引采用同一归一化规则。
- [ ] 固定依赖版本、内置词典及分词策略，将其摘要纳入索引身份；不提供运行时热换词典。
- [ ] 高亮基于正文位置复核，不使用预分词文本的位置冒充源码位置。
- [ ] 分词、记录交付、FTS、候选枚举及源码输出接入既有资源预算和取消机制；不通过静默裁剪伪装完整结果。

### 生命周期与版本

- [ ] 新增 GRA1 注释及关联交付契约，接入 staging、引用校验、owner 替换和封存。
- [ ] 全量导入后构建 FTS；增量替换同步清理旧记录，封存时验证 FTS 与正文一致。
- [ ] 注释独改按源码 hash 更新当前 owner；保持 Java 契约指纹忽略注释，不扩大无关消费者重算。
- [ ] 代码独改也重新计算注释归属、位置及附近语句。
- [ ] 零注释、删除、改名、语言禁用、world 删除均显式清理旧事实。
- [ ] Python 沿用当前变更后全量重算策略。
- [ ] 分词及关联规则变化使旧 profile 不可复用；首期要求全量重建。
- [ ] 注释与代码在同一 candidate 中发布；取消、失败或 CAS 冲突保留旧 head。
- [ ] 历史查询使用固定 revision 的捕获源码；续页不读取当前工作区。
- [ ] 注释表随 facts.db 回收，源码继续遵守现有 blob 引用保护。
- [ ] 同步升级受影响的图模型、行契约、物理/逻辑 schema、Java 编译器模型和相关版本门禁；C ABI 入口不变则保留 ABI 版本。
- [ ] 旧图库按现有规则要求 `index --full`，成功建立新 revision 后切 head。
- [ ] DDL 修改生成输入及生成器后重新生成，不直接修改生成的紧凑 DDL；同步导入、打包和覆盖映射。

## 4. 测试与验收

| 测试组 | 必测场景 | 通过标准 |
|---|---|---|
| Java fixture | Javadoc、方法内、行尾、文件头、嵌套作用域、Unicode 转义、字符串伪注释 | 提取范围正确，关联无跨作用域误挂 |
| Rust / Python fixture | 内外文档、嵌套块注释、doc 属性、docstring、普通字符串 | 符合语言规则，不把普通字符串误判为注释 |
| 上下文配置 | 默认 5/5、非对称值、0、100、非法值、文件首尾、多行注释、跨方法窗口 | 返回精确行范围；CLI 覆盖及配置实际生效 |
| 检索 | 中文、混合标识符、标点、重复词、同方法多注释、孤立注释 | 预期召回、稳定去重、证据完整 |
| 位置映射 | 中文、emoji、CRLF、去除注释标记 | 字节范围、UTF-16 行列、高亮一致 |
| 增量 | 注释独改、代码独改、插入空行、删除全部注释、方法删除、文件改名 | 同输入 full/delta 规范化内容一致，无旧词残留 |
| 隔离 | 同文件不同 world、同名方法、模块/scope 过滤 | 无跨上下文串联 |
| 历史与分页 | 查询后改工作区、发布新 revision、修改配置、续页 | 原查询结果及上下文不漂移 |
| 故障与预算 | worker 崩溃、取消、断流、磁盘失败、超大注释、查询截断 | 不发布半成品，旧 head 保留，限制明确披露 |
| 存储 | FK、FTS 完整性、删除清理、旧格式拒绝 | 校验通过，重建要求明确 |
| 配置与规则失效 | 只修改展示配置、升级分词规则、语言禁用、world 删除 | 展示变更不重建语义图；规则升级不复用旧索引；停用后无旧事实 |

执行顺序：

1. [ ] `just test-java`，Java 分析及模型 fixture 优先。
2. [ ] Rust/Python 注释 fixture、共享存储与查询回归。
3. [ ] `just test-rust`、`just test-python`，验证 CLI/RPC/pipeline/config 完整链路。
4. [ ] `just test-java-native`、`just test-java-release`、Python 分发及混合语言回归；分发检查遵守原可执行路径恢复和禁止混装约束。
5. [ ] 冻结 iopengw HEAD `267c7ced4993aa88613f8f17a8099943fec98159`，仅使用已提交内容进行功能验收；建立明确的注释命中及方法定位预期集。
6. [ ] 性能仅做一轮：固定输入、空应用状态、预算及产物，记录耗时、进程树峰值内存、图库大小、注释与关联数量、固定查询集结果；保留原失败回执，不区分 Native 冷热。

所有测试记录区分计划、实际执行和验收结论；fixture 或开发构建通过不写成正式放行。不得把历史性能数字作为本功能当前版本的测量结果。
